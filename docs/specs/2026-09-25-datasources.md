# 数据源、网络通道与能力探测

> Status: Draft
> Owner: OpsNap 产品负责人
> Last updated: 2026-09-25

**Objective:** 管理员能在「数据源」页添加 MySQL、PostgreSQL 与服务器文件三类数据源。数据源可以经由可复用的「网络通道」（SSH 跳板、SOCKS5 代理，可混合组成多级链路）连接。保存后 OpsNap 自动探测该数据源支持哪些备份方式，对可修复的问题给出可直接复制的修复方法。

**Hard invariant:**

1. 秘密不以明文落盘，也不写入日志，任何接口都不返回。秘密包括：数据库密码、SSH 密码与私钥、私钥口令、SOCKS5 密码、TLS 客户端私钥。
2. SSH 主机密钥未经用户确认，或与保存的不一致时，OpsNap 不向这台主机发送任何凭据，也不经由它转发任何连接。
3. 连接测试与能力探测都是只读的，不修改数据源上的任何配置或数据。唯一的例外是“临时目录能否执行程序”这一项，它会写入一个临时文件并在检查后删除。

标记说明：〔已核实〕= 查证过源码或官方资料；〔用户决定〕= 本轮讨论中用户已确认；〔默认〕= 按常规做法先定、用户已认可设计。

## 问题

1. **还没有数据源。** 侧栏「数据源」仍是占位页（`frontend/src/App.tsx:27` 渲染 `ComingSoonPage`）〔已核实，main 202a25c〕。第 2 轮的备份任务没有可选的备份对象。
2. **自建环境的数据库往往不能直连。** 常见的情况是：数据库只能经过堡垒机访问，或者要先经过办公网的 SOCKS5 代理，再经过堡垒机〔用户决定：需要 SSH 与 SOCKS5 混合的多级链路〕。
3. **增量能力要提前知道。** 这来自 v1 spec 的用户故事 2：新建任务之前就要知道缺什么条件，而不是等到恢复时才发现增量没在收。

## 角色与用户故事

1. 作为**管理员**，我想把一台只能经堡垒机访问的 MySQL 加为数据源，堡垒机配置一次就能被多个数据源共用。
2. 作为**管理员**，我想在保存数据源后立即看到它支持哪些备份方式、缺什么条件，以及具体怎么修。
3. 作为**管理员**，我想在堡垒机的主机密钥变化时得到明确提示，而不是在不知情的情况下把凭据发给一台陌生主机。

## 设计决策

| # | 决策 | 依据与被否决的方案 |
|---|---|---|
| 1 | 本轮的数据源类型为 MySQL、PostgreSQL、服务器文件〔用户决定〕 | 第 2 轮（MySQL/PG 备份）与第 4 轮（服务器文件）直接需要这三类。否决：本轮做全部六类——MongoDB、Redis、Kafka 的连接细节（副本集 URI、SASL 等）在第 5 轮随备份一起确定，更不容易返工 |
| 2 | 能力探测与数据源管理合为一个 spec、一次交付〔用户决定〕 | 否决：拆成“数据源与连接链路”和“能力探测”两个 spec 依次交付 |
| 3 | 服务器文件数据源只是一台 SSH 主机，备份路径在任务中选择〔用户决定〕 | 与设计稿中任务向导第 2 步（选择路径与排除规则）一致；一台主机可以被多个任务以不同路径使用，和 MySQL 数据源是实例、任务再选库的方式相同。修订 v1 spec 中“一台 SSH 可达的主机加上目录”。否决：主机加一个根目录（同一主机上两个不相关的目录要建两个数据源） |
| 4 | 跳板与代理是独立、可复用的「网络通道」〔用户决定〕 | 一台堡垒机被多个数据源共用时，凭据与主机密钥只需维护一处。否决：在每个数据源里内联填写链路 |
| 5 | 每个通道是一跳，可以指定“经由”另一个通道，从而组成链路；数据源只选最后一跳〔用户决定〕 | 链路只配置一次，所有数据源共用；在某跳之前再加一跳，只需修改一个通道。否决：由数据源按顺序排列多个通道；把一整条链路做成一个通道（共用的堡垒机的凭据会被重复保存） |
| 6 | 通道类型为 SSH 跳板与 SOCKS5 代理，两者可以任意混合〔用户决定〕 | 否决：HTTP 代理（本轮不做） |
| 7 | 网络通道作为「数据源」页中的一个分页〔用户决定〕 | 侧栏导航保持 v1 信息架构不变。否决：侧栏新增一项；放进「设置」（通道属于业务配置，放在那里不好找） |
| 8 | SSH 主机密钥在首次连接时由用户确认，以后不一致就拒绝连接，直到用户重新确认〔用户决定〕 | 与 OpenSSH known_hosts 的模型一致，但不依赖主控端的文件。否决：要求用户事先粘贴公钥（太繁琐）；不校验（存在中间人风险，凭据可能被截获） |
| 9 | SSH 认证支持密码与私钥（可带口令）；数据库 TLS 支持客户端证书（mTLS）〔用户决定〕 | 否决：SSH agent、SSH 用户证书、主机 CA（本轮都不做）。因此路径相关的服务器文件探测项（LVM、文件系统、文件数量与大小）移到任务向导第 2 步，这修订了 v1 spec 的探测表 |
| 10 | 连接层是统一的拨号抽象：每种通道各实现一跳，链路是逐跳叠加；数据库驱动与 SSH 客户端都经由它建立连接；探测项按类型注册、互不依赖〔用户决定：做好抽象，高内聚、低耦合〕 | 以后新增通道类型或数据源类型时，只需新增实现，不修改已有代码。否决：各数据源类型各自实现隧道逻辑 |

## 网络通道

**前提**：已登录（浏览器会话或 API 令牌）。

**字段**：

- 名称：1–64 个字符，在通道之间不能重名。
- 类型：SSH 跳板，或 SOCKS5 代理。
- 主机与端口。端口范围 1–65535，SSH 默认 22，SOCKS5 默认 1080。
- **SSH 跳板**：
  - 用户名；
  - 认证方式为密码或私钥二选一。
  - 私钥可以粘贴或上传，支持 OpenSSH 与 PEM 格式的 RSA、ECDSA、Ed25519 私钥。私钥已加密时必须填写口令：缺少口令或口令错误时，在对应字段旁提示；格式无法识别时，在私钥字段旁提示。
  - 切换认证方式并保存后，原来那种方式的凭据被删除。
- **SOCKS5 代理**：
  - 用户名和密码可选，两者要么都填，要么都不填；
  - 目标主机名交给代理端解析（socks5h 语义）〔默认〕。
- **经由**：可选。选定后，到达本通道的连接要先经过所选通道。
  - 不能选自己，也不能选会形成环路的通道，这两种情况在选择框中不可选；
  - 从 OpsNap 出发的整条链路最多 5 跳〔默认〕，超出时不能保存，并提示当前链路长度；
  - 表单下方实时显示完整链路，例如“OpsNap → office-socks (SOCKS5) → bastion.corp:22”。

**测试连接**：沿链路依次建立连接。

- SSH 跳：连通、主机密钥、认证；
- SOCKS5 跳：连通，以及方法协商和认证；
- 失败时指出是第几跳、哪个通道，以及具体原因，例如“第 1 跳 office-socks（SOCKS5）：认证失败”“第 2 跳 bastion-prod（SSH）：连接超时”；
- 整次测试的超时为 30 秒〔默认〕。

**保存**：只有测试成功才能保存，编辑时同样先测试。编辑时，秘密字段显示“已保存（加密存储）”，留空表示不修改。编辑失败或中途取消时，通道保持编辑前的全部设置。

**列表**（「数据源」页的「网络通道」分页）：

- 每行显示：
  - 名称与类型；
  - 地址：`ssh://user@host:port` 或 `socks5://host:port`；
  - 经由的链路与认证方式；
  - “被 N 个数据源 · M 个通道使用”；
  - 状态，以及最近一次测试的时间或原因。
- 状态为以下三种之一：
  - **正常**；
  - **无法连接**：附原因；
  - **主机密钥已变化**：仅 SSH。这一行提供“重新确认”，见「主机密钥」。
- 行操作：测试连接、编辑，以及更多菜单中的“删除通道”。
- 通道仍被数据源或其他通道引用时不能删除：菜单项不可用，并列出引用它的对象。
- 删除时二次确认，只删除 OpsNap 中的记录与凭据。
- 没有通道时显示空状态，引导“新建通道”。

## 数据源

**前提**：已登录（浏览器会话或 API 令牌）。

**通用字段**：

- 名称：1–64 个字符，在数据源之间不能重名。
- 类型：MySQL、PostgreSQL、服务器文件。
- 主机与端口，范围 1–65535。默认端口：MySQL 3306、PostgreSQL 5432、服务器文件 22。
- 网络通道：可选，不选则由 OpsNap 直连。表单下方实时显示完整链路，最后一跳是数据源本身。
- 同一个地址可以被多个数据源使用，例如用不同账号备份同一个实例〔默认〕。

**MySQL / PostgreSQL**：

- 用户名、密码。PostgreSQL 多一项“连接数据库”，默认 `postgres`。
- TLS 模式有五档：
  - 不加密；
  - 优先加密（默认）：服务端支持就加密，不校验证书，不支持则不加密；
  - 必须加密：不校验证书；
  - 校验 CA；
  - 校验 CA 与主机名。
- CA 证书可选：两种“校验”模式下未提供 CA 时，使用主控端系统的信任库〔默认〕。
- 客户端证书与客户端私钥（mTLS）可选，但必须同时提供；无法解析或两者不匹配时，在字段旁提示。
- 连接测试：沿链路建立连接、认证，读取服务端版本；如果使用了 TLS，还要报告 TLS 版本和是否校验了证书。

**服务器文件**：

- 用户名，认证方式与 SSH 跳板相同（密码或私钥）。
- 连接测试：沿链路建立连接、确认主机密钥、认证，然后执行 `uname -sm` 读取系统与架构。

**测试与保存规则**：与网络通道相同（先测试后保存，30 秒超时，失败时指出第几跳）。认证失败、连接超时、主机不存在、TLS 握手失败、证书校验失败等原因都要按原文显示。

**列表**（「数据源」分页）：

- 每行显示：
  - 名称与类型；
  - 地址：`mysql://host:port`、`postgres://host:port`、`ssh://user@host:port`；
  - 服务端版本与链路，例如“MySQL 8.0.36 · 经 office-socks → bastion-prod”，直连时显示“直连”；
  - 探测摘要：“N 通过 · M 提醒 · K 不可用”，零项的档位不显示，全部通过时显示“N 项全部通过”；此外还有“探测中”“无法探测”两种情况；
  - 状态，以及最近一次测试的时间或原因。
- 状态为以下三种之一：
  - **正常**；
  - **无法连接**：附原因；
  - **主机密钥已变化**：链路中某个 SSH 通道或目标主机的密钥不一致，同时指明是哪一台。这一行提供“重新确认”。
- 测试时机：
  - 创建时；
  - 保存编辑时；
  - 点击“测试连接”时；
  - 重新确认主机密钥之后。
- 打开列表不会自动测试。
- 行操作：测试连接、编辑，以及更多菜单中的“查看详情”“删除数据源”。点击名称进入详情页。
- 删除时二次确认，只删除 OpsNap 中的记录与凭据，不影响数据库或服务器。后续轮次有任务引用该数据源时禁止删除，本轮不涉及。
- 没有数据源时显示空状态，引导“新建数据源”；加载失败时显示错误与重试，不出现空白页。

## 主机密钥

适用于每一台 SSH 主机，包括 SSH 跳板通道与服务器文件数据源。

- **首次连接**：测试进行到这台主机时暂停，弹出“确认主机密钥”。
  - 弹窗显示主机地址、经由的链路、密钥类型，以及完整的 SHA256 指纹，并提示可以在服务器上用 `ssh-keygen -lf <公钥文件>` 核对；
  - 用户选择“信任并继续”后测试继续，这把密钥随通道或数据源一起保存；
  - 用户取消时测试中止，什么也不保存。
- **密钥变化**：之后任何连接中，如果这台主机出示的密钥与保存的不一致，就立即中止连接，不进行认证。
  - 对应的通道或数据源状态变为“主机密钥已变化”；
  - 经过这个通道的数据源，状态同样变为“主机密钥已变化”，并指明是哪个通道。
- **重新确认**：在列表的“重新确认”或编辑表单中打开“主机密钥已变化”弹窗。
  - 弹窗并列显示保存的指纹与现在出示的指纹；
  - 弹窗提醒：服务器重装会导致密钥变化，但也可能是中间人攻击，应先与服务器管理员核对；
  - 用户选择“信任新密钥”后，保存新密钥，并重新测试这台主机本身，以及所有经过它的数据源。

## 能力探测

**前提**：数据源已保存。

**时机**：

- 数据源保存成功后，自动在后台探测一次，列表中这一行显示“探测中”。
- 在详情页点击“重新探测”。
- 以后任务向导第 2 步也会触发探测（第 2 轮）。
- 同一数据源同时只进行一次探测，探测进行中时“重新探测”按钮不可用。

**结果**：

- 每个探测项分三档：**可用**、**可用但有风险**（提醒）、**不可用**。
- “有风险”与“不可用”都说明原因。可以修复的项，给出可直接复制的修复方法（SQL、配置项或命令），并说明在哪里执行。
- 结果带探测时间，保存在 OpsNap 中。
- 连接失败或超时时，整次结果显示为“无法探测”并附错误信息，不显示上一次的结果冒充本次。
- 单次探测的超时为 60 秒〔默认〕。

**MySQL 探测项**：

| 探测项 | 可用 | 有风险 | 不可用 | 修复方法 |
|---|---|---|---|---|
| 版本 | 读到版本号 | — | — | — |
| binlog | `log_bin = ON` | — | 未开启（增量不可用） | `my.cnf` 中设置 `log_bin`（需重启） |
| binlog 格式 | `ROW` | — | 不是 ROW（增量不可用） | `SET PERSIST binlog_format = 'ROW';` |
| GTID | `gtid_mode = ON` | 未开启（增量只能按位点续传） | — | `my.cnf` 中设置 `gtid_mode=ON`、`enforce_gtid_consistency=ON` |
| binlog 保留时长 | 不少于 7 天 | 少于 7 天（中断超过这个时长就无法续传）〔默认阈值〕 | — | `SET PERSIST binlog_expire_logs_seconds = 604800;` |
| 复制权限 | 有 REPLICATION SLAVE 与 REPLICATION CLIENT | — | 缺少任一项（增量不可用） | `GRANT REPLICATION SLAVE, REPLICATION CLIENT ON *.* TO '<用户>'@'<主机>';` |
| 非 InnoDB 表 | 没有 | 存在（全量时需要锁表），列出最多 5 张表名与总数 | — | — |
| 主控端 `mysqldump` | 已找到，且版本不低于服务端的大版本与次版本 | 版本低于服务端 | 找不到（全量不可用） | 安装匹配版本的 MySQL 客户端，或使用 OpsNap Docker 镜像 |

**PostgreSQL 探测项**：

| 探测项 | 可用 | 有风险 | 不可用 | 修复方法 |
|---|---|---|---|---|
| 版本 | 读到版本号 | — | — | — |
| `wal_level` | `replica` 或 `logical` | — | `minimal`（物理模式与 WAL 增量不可用） | `ALTER SYSTEM SET wal_level = 'replica';`（需重启） |
| `max_wal_senders` | 大于 0 | — | 为 0（同上） | `ALTER SYSTEM SET max_wal_senders = 10;`（需重启） |
| 复制槽余量 | `max_replication_slots` 减去已用数量至少为 1 | — | 没有余量（WAL 增量不可用） | `ALTER SYSTEM SET max_replication_slots = <已用 + 2>;`（需重启） |
| REPLICATION 属性 | 账号有此属性或为超级用户 | — | 没有（物理模式不可用） | `ALTER ROLE <用户> REPLICATION;` |
| 主控端 `pg_dump` | 已找到，且大版本不低于服务端 | — | 找不到，或大版本低于服务端（逻辑全量不可用） | 安装匹配大版本的 PostgreSQL 客户端，或使用 OpsNap Docker 镜像 |

**服务器文件探测项**：

| 探测项 | 可用 | 有风险 | 不可用 | 修复方法 |
|---|---|---|---|---|
| SSH 可达 | 连接并认证成功 | — | —（失败即“无法探测”） | — |
| CPU 架构 | amd64 或 arm64 | — | 其他架构（临时执行器不可用） | — |
| 临时目录可执行 | 能在临时目录写入并执行一个测试程序 | — | 不能（临时执行器不可用），附原因（如 `noexec`） | 为临时目录去掉 `noexec`，例如 `mount -o remount,exec /tmp` |
| 免密 sudo | `sudo -n true` 成功 | 失败（文件系统快照需要 root 权限，直接读取不受影响） | — | 在 sudoers 中为该用户添加 `NOPASSWD` 规则（给出示例行） |

路径相关的项（是否位于 LVM 卷、卷组剩余空间、文件系统类型、文件数量与总大小估算）在任务向导第 2 步选定路径后探测，不属于本轮。

**主控端工具的查找顺序**：先在 PATH 中查找，再在配置项 `tools.dir` 指定的目录中查找〔默认〕，为以后预装多个版本的 Docker 镜像做准备。

## 数据源详情页

**前提**：已登录。在列表中点击名称或选择“查看详情”进入，地址为 `/sources/<id>`。

- **头部**：
  - 返回「数据源」；
  - 名称与状态，以及版本、地址、最近测试时间；
  - 操作按钮：测试连接、编辑、重新探测。
- **连接**：
  - 类型、地址、用户名、TLS 模式（使用中的 TLS 版本、是否带客户端证书）、最近一次测试的结果；
  - 完整的网络链路：从 OpsNap 开始逐跳列出，每跳显示名称、类型与地址，SSH 跳还显示主机密钥指纹。
- **能力探测**：
  - 摘要与探测时间；
  - 逐项的状态、实际读到的值与说明；
  - 有风险和不可用的项附修复方法与“复制”按钮。
- 数据源不存在时显示“数据源不存在”，并提供返回列表的入口。

## 敏感数据

- 所有秘密都用认证 spec 中的主密钥加密后存入数据库。
- 日志中不出现秘密，也不出现 SSH 私钥内容、数据库连接串中的密码。
- 任何接口都不返回秘密。编辑表单只显示“已保存（加密存储）”。
- 连接测试与探测的错误信息如果包含秘密（例如驱动把连接串回显在错误里），必须先去掉秘密再显示或记录。

## 权限

- 浏览器会话与 API 令牌都可以管理数据源与网络通道，包括查看、增删改、测试、确认主机密钥、探测，因为这些操作都不会取回秘密〔默认，与存储一致〕。

## 界面

- 页面与弹窗按设计稿实现：
  - 数据源列表与网络通道列表（同一页的两个分页）；
  - 新建或编辑数据源（三种类型）；
  - 新建或编辑通道（两种类型）；
  - 确认主机密钥；
  - 主机密钥已变化；
  - 删除确认；
  - 数据源详情。
- 所有文案提供中文与英文，深色与浅色主题都要可用，颜色与字号只使用设计变量。
- 测试连接、保存、重新探测、信任主机密钥时，按钮显示加载状态，并禁止重复提交。
- 出错时在表单顶部或对应字段旁显示原因，不出现空白页。
- 提交进行中不能关闭对话框。
