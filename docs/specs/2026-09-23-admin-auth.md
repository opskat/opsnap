# 管理员认证、OIDC 与 API 令牌

> Status: Approved
> Owner: OpsNap 产品负责人
> Last updated: 2026-09-23

**Objective:** 部署 OpsNap 后，只有持有启动日志中设置码的人能创建唯一的管理员；之后访问控制台必须先用密码或已绑定的 OIDC 身份登录，脚本则使用可吊销、可设有效期的 API 令牌调用 API。

**Hard invariant:**

1. 未认证的请求只能访问下文「公开接口」列出的接口，其余接口一律返回 401，页面一律跳转到登录页。
2. 密码、会话、API 令牌、OIDC Client Secret 都不能以明文落盘或写入日志。令牌完整值只在生成时显示一次。
3. 任何设置组合都不能让管理员失去全部登录方式：关闭密码登录前必须已有可用的 OIDC 登录，并且始终可以在服务器上用命令行恢复密码登录。

标记说明：〔已核实〕= 查证过源码或官方资料；〔用户决定〕= 本轮讨论中用户已确认；〔默认〕= 按常规做法先定、用户已认可。设计稿见 `/Users/codfrm/Code/设计稿/opsnap.pen` 中的「登录 · Dark」「首次设置 · Dark」「设置 · 账号与 API 令牌 · Dark」和三张弹窗稿，仅作参考，以本文为准。

本文是 [OpsNap v1 spec](2026-09-23-opsnap-v1.md)「交付拆分」第 1 轮中认证部分的细化，并修订了该 spec 的决策 15。

## 问题

1. **当前主干上没有任何认证。** 骨架只有 `GET /api/v1/system/health` 一个接口，所有页面对任何访问者开放〔已核实，main 54edf11〕。后续的数据源和存储会保存数据库密码与云存储凭据，没有认证就不能继续开发。
2. **“第一个访问者直接设置管理员”会被抢注。** 实例部署在公网时，攻击者可能在运维打开页面之前就创建了管理员〔用户决定采用设置码〕。
3. **团队希望用已有的统一登录。** 用户要求登录支持 OIDC〔用户陈述〕。

## 角色与用户故事

1. 作为**部署者**，我想用只有我能看到的设置码完成初始化，这样实例暴露在公网时也不会被别人抢先创建管理员。
2. 作为**管理员**，我想用公司的 OIDC 统一登录进入控制台，必要时关闭密码登录，满足统一 SSO 的要求。
3. 作为**管理员**，我想在忘记密码或 IdP 故障时，能在服务器上用命令行恢复登录。
4. 作为**脚本或 CI 的维护者**，我想用一个有名字、有有效期、可吊销的令牌调用 API，并且能看到它最近什么时候被用过。

## 设计决策

| # | 决策 | 依据与被否决的方案 |
|---|---|---|
| 1 | 首次设置需要输入启动日志打印的一次性设置码〔用户决定〕 | 防止公网实例被抢注。否决：第一个访问者直接设置（会被抢注）；只能用命令行创建（与 v1 spec“首次启动时引导设置”不符） |
| 2 | 忘记密码时在服务器上执行 `opsnap admin reset-password`〔用户决定〕 | 能登录服务器即证明有权限。否决：删除管理员后重走首次设置（步骤多）；不提供找回 |
| 3 | API 令牌拥有全部业务 API 权限，可选有效期，但不能管理令牌、不能修改密码或登录方式〔用户决定〕 | 令牌泄露时不能被用来锁死管理员。否决：永不过期的全权令牌；只读 / 读写分级（spec 未要求，工作量大） |
| 4 | OIDC 绑定到唯一管理员：最多绑定一个 OIDC 身份（issuer + sub）〔用户决定〕 | 保持单管理员模型不变。否决：按邮箱或组白名单允许多人登录（等于多用户，还会带出审计需求） |
| 5 | 密码登录默认开启；绑定 OIDC 并用它成功登录过一次后，才允许关闭〔用户决定〕 | 满足“只允许 SSO”，又不会误锁。否决：密码登录永远不能关闭 |
| 6 | 敏感配置用主密钥加密落盘；主密钥默认是数据目录下自动生成的 `master.key`，设置环境变量 `OPSNAP_MASTER_KEY` 时改用环境变量〔用户决定〕 | 开箱即用，密钥文件与数据库分开保存。否决：必须通过环境变量提供（忘了设就启动不了）。此机制原计划放在存储那份 spec，因 OIDC Client Secret 需要加密而提前到本文，后续存储凭据、数据源密码、仓库密钥都复用它 |
| 7 | 浏览器会话保存在服务端，用 HttpOnly Cookie 标识，连续 7 天不使用即过期〔默认〕 | 退出、改密码时可以立即让会话失效。否决：把 JWT 存在浏览器 localStorage（无法服务端吊销，易被脚本读取） |
| 8 | 登录失败按来源 IP 限速：15 分钟内连续失败 5 次，该 IP 被拒绝 15 分钟〔默认〕 | 防暴力破解，又不会让别人故意输错把管理员锁在外面。否决：按账号锁定 |
| 9 | 密码至少 12 个字符，不设其他复杂度规则〔默认〕 | 长度比字符种类更有效。否决：强制大小写、数字、符号组合 |
| 10 | 修订 v1 spec 决策 15 为“单管理员账号，可选绑定一个 OIDC 身份；可生成的 API 令牌”〔用户决定〕 | 本轮新增 OIDC 需求 |

## 公开接口

未登录时只有以下接口可以访问，其余 `/api/` 接口返回 401：

- 健康检查
- 查询初始化状态：是否已创建管理员、是否开启密码登录、是否配置了 OIDC 及其显示名称
- 首次设置（仅在尚未创建管理员时可用）
- 密码登录（仅在密码登录开启时可用）
- 发起 OIDC 登录，以及 OIDC 回调

前端页面本身（静态资源）可以加载，但除登录页和首次设置页外，页面在确认未登录后立即跳转到登录页；登录成功后回到原本要访问的页面。

## 首次设置

**前提**：数据库中还没有管理员。

- 每次服务启动且尚未创建管理员时，生成一个新的设置码，并在启动日志中以醒目的一行打印出来（例如 `OpsNap 设置码：K7QF-2MXP-9DVA`）。设置码只保存在进程内存中，重启即作废并换新。
- 未创建管理员时，访问任何页面都会跳转到首次设置页。页面要求填写设置码、用户名、密码和确认密码，并提示在启动日志中查找设置码（Docker 部署可执行 `docker logs <容器名>`）。
- 用户名为 3–32 个字符，只允许小写字母、数字以及 `.` `_` `-`。密码至少 12 个字符，两次输入必须一致。不合法的字段在旁边显示错误，不能提交。
- 设置码错误时提示“设置码不正确”，并计入第「登录保护」一节的失败次数。
- 创建成功后直接进入已登录状态，跳转到概览页。此后首次设置接口永久返回“已初始化”错误，首次设置页不再出现（访问会跳转到登录页），启动日志不再打印设置码。
- 两个请求同时提交首次设置时，只有一个能成功，另一个收到“已初始化”错误。

## 密码登录

**前提**：已创建管理员，密码登录处于开启状态。

- 登录页有用户名和密码两个输入框。用户名或密码错误时统一提示“用户名或密码错误”，不区分是哪一项错误。
- 登录成功后创建会话，跳转到登录前要访问的页面，没有则去概览页。
- 密码登录已关闭时，登录页不显示用户名和密码输入框，只显示 OIDC 登录按钮；直接调用密码登录接口返回“密码登录已关闭”。
- 登录页和首次设置页都提供语言与主题切换，与控制台内的设置一致。
- 登录页底部提示：忘记密码时在服务器上执行 `opsnap admin reset-password`。

## 登录保护

- 同一来源 IP 在 15 分钟内连续失败 5 次（密码错误、设置码错误都算），此后 15 分钟内该 IP 的密码登录和首次设置请求直接被拒绝，页面提示“尝试次数过多，请在 N 分钟后重试”。一次成功登录会清零该 IP 的失败计数。
- 限速不锁定管理员账号：其他 IP 仍可正常登录，OIDC 登录不受影响。
- 限速状态只在内存中，服务重启后清零。
- 来源 IP 取 TCP 连接的对端地址；只有在配置中声明了可信反向代理地址时，才使用 `X-Forwarded-For` 中的地址。

## 会话

- 登录成功后，服务端保存会话，浏览器通过 HttpOnly、SameSite=Lax 的 Cookie 持有会话标识；通过 HTTPS 访问时 Cookie 带 Secure 标记。
- 会话连续 7 天没有请求即过期；每次请求会顺延过期时间。过期后访问页面跳转到登录页，调用接口返回 401。
- 侧栏底部显示当前用户名和“退出登录”按钮。退出后该会话立即失效，再用同一 Cookie 请求返回 401。
- 使用 Cookie 认证的写请求（非 GET/HEAD）必须来自同源：请求头 `Origin` 与当前站点不一致的写请求返回 403，防止跨站请求伪造。
- 设置页「账号」卡片显示用户名、密码最后修改时间，以及当前会话的浏览器、来源 IP 和过期时间。

## 修改密码与命令行重置

**修改密码**（设置页 → 修改密码）：

- 要求输入当前密码、新密码和确认新密码。当前密码错误时在该字段旁提示“当前密码不正确”，并计入登录保护的失败次数。
- 修改成功后，除当前浏览器外的所有会话立即失效；当前浏览器保持登录。API 令牌不受影响。
- 只能通过浏览器会话调用；用 API 令牌调用返回 403。

**命令行重置**（`opsnap admin reset-password`）：

- 在服务器上执行（Docker 部署用 `docker exec`）。在交互终端中提示输入并确认新密码，输入不回显；非交互环境使用 `--password-stdin` 从标准输入读取。新密码同样至少 12 个字符。
- 服务正在运行时也可以执行，效果立即生效。
- 成功后：设置新密码；所有浏览器会话立即失效；如果密码登录处于关闭状态，重新开启它。API 令牌和 OIDC 绑定保持不变。命令输出“已重置管理员密码，所有登录会话已失效”，若重新开启了密码登录，则一并说明。
- 尚未创建管理员时，命令失败并提示“尚未创建管理员，请通过网页完成首次设置”。

## OIDC

### 配置

**前提**：已用浏览器会话登录。以下操作用 API 令牌调用一律返回 403。

- 设置页「登录方式」卡片中可配置一个 OIDC 提供方：显示名称（用于登录按钮“使用 <显示名称> 登录”）、Issuer URL、Client ID、Client Secret、Scopes（默认 `openid profile email`）。
- 回调地址由当前浏览器访问的站点地址加固定路径生成，保存配置时一并记录，并在卡片上显示、可复制，供用户在 IdP 中注册。之后 OpsNap 始终使用这个记录的地址发起登录。
- 保存时从 Issuer 拉取 OIDC discovery 文档。拉取失败、文档无效或 Issuer 不一致时，不保存，并显示失败原因（例如“无法连接 https://sso.example.com：连接超时”）。
- Client Secret 保存后只显示“已保存（加密存储）”，不会返回给前端。编辑时留空表示不修改。
- 修改 Issuer 或 Client ID 会清除已有的绑定（身份属于原来的提供方）；如果此时密码登录是关闭的，同时重新开启密码登录。保存前要明确提示这一后果并二次确认。

### 绑定

- 配置保存后，卡片显示“未绑定”和“绑定”按钮。点击后跳转到 IdP 登录，回来后把该 OIDC 身份（issuer + sub）绑定到管理员，卡片显示“已绑定”以及身份的邮箱（没有邮箱时显示 `preferred_username`，都没有时只显示 sub）。
- 只能绑定一个身份。已绑定时再次绑定会先要求解除当前绑定。
- 解除绑定需要二次确认。如果密码登录处于关闭状态，解除时自动重新开启密码登录，并在确认框里提前说明。

### 登录

**前提**：已配置 OIDC 并已绑定身份。

- 登录页在密码登录表单下方显示“或”分隔线和“使用 <显示名称> 登录”按钮；未配置或未绑定时不显示。
- 点击后跳转到 IdP；回调时校验 state、nonce 与 PKCE，以及 ID Token 的签名、issuer、audience 和有效期。
- 回调中的身份与已绑定身份一致时，创建会话（与密码登录的会话完全相同），跳转到登录前要访问的页面。
- 以下情况回到登录页并显示对应错误，不创建会话：
  - 身份与绑定的不一致：“此 OIDC 账号未绑定到 OpsNap”
  - 用户在 IdP 取消或 IdP 返回错误：“OIDC 登录已取消或失败：<IdP 返回的错误描述>”
  - state 不匹配、回调已过期（发起后超过 10 分钟）或 Token 校验失败：“OIDC 登录校验失败，请重试”
  - 无法连接 IdP：“无法连接 OIDC 提供方”
- 首次用 OIDC 成功登录后，记录“已通过 OIDC 登录过”，此后才允许关闭密码登录。

### 关闭密码登录

- 「登录方式」卡片中的“密码登录”开关默认开启。
- 只有已绑定 OIDC 且已通过 OIDC 成功登录过至少一次时，开关才可以关闭；否则开关不可操作，并提示原因。
- 关闭需要二次确认，确认框说明：关闭后只能通过 OIDC 登录；IdP 不可用时，在服务器上执行 `opsnap admin reset-password` 可以重新开启。
- 关闭后已有的会话不受影响。

## API 令牌

**前提**：已用浏览器会话登录。生成、查看列表、吊销令牌只能通过浏览器会话进行；用 API 令牌调用这些接口返回 403。

- **生成**：填写名称和有效期（30 天 / 90 天 / 1 年 / 永不过期，默认 90 天），下方实时显示具体过期日期。名称为 1–64 个字符，不能与其他未吊销、未过期的令牌重名，否则在字段旁提示。
- **只显示一次**：生成后弹窗显示完整令牌和复制按钮，并警告“令牌只显示这一次，关闭后无法再次查看”。关闭弹窗后，任何接口都不再返回完整令牌。令牌以 `onp_` 开头，数据库只保存其哈希。
- **列表**：显示名称、令牌前缀（例如 `onp_7Hq2…`）、创建时间、最近使用时间（从未使用时显示“从未使用”）、过期时间。已过期的令牌带“已过期”标签；已吊销的令牌整行变灰并带“已吊销”标签。列表不提供删除。
- **吊销**：二次确认后立即生效，此后使用该令牌的请求返回 401。
- **使用**：请求头 `Authorization: Bearer <令牌>`。有效令牌可以调用全部业务 API，但不能调用上文列出的账号类接口（修改密码、登录方式、令牌管理），这些返回 403。令牌请求不受 Origin 检查限制，也不会创建会话。
- **失效反馈**：令牌不存在、已吊销或已过期时返回 401，错误信息分别说明“令牌无效”“令牌已吊销”“令牌已过期”。
- **最近使用时间**：每次成功认证后更新，精度到分钟（同一分钟内的多次使用只记一次）。
- 修改密码、命令行重置密码、修改 OIDC 配置都不影响已有令牌。

## 敏感数据的存储

- **主密钥**：首次启动时，如果没有设置 `OPSNAP_MASTER_KEY`，在数据目录生成随机的 `master.key`，文件权限为 0600。设置了 `OPSNAP_MASTER_KEY` 时使用它，不读写 `master.key`。环境变量的格式要求在产品文档中说明，格式不对时拒绝启动并说明原因。
- **加密范围**：本文中需要还原的敏感值（OIDC Client Secret）用主密钥加密后存入数据库。不需要还原的值只存单向哈希：管理员密码使用专门的慢哈希算法，会话标识和 API 令牌使用哈希。
- **密钥不匹配**：数据库中已有加密数据，但主密钥缺失或与加密时使用的不一致时，服务拒绝启动，日志说明“主密钥与数据库不匹配”以及应检查的位置。**不能**自动生成新密钥覆盖，也不能在无法解密的情况下继续运行。
- **日志**：密码、会话标识、令牌、Client Secret 以及 OIDC 的授权码和 Token 都不写入日志。唯一的例外是设置码：它在每次启动（仍未创建管理员时）的日志中打印一次。
- **文档**：产品文档必须说明：迁移或恢复 OpsNap 时，必须把 `master.key`（或 `OPSNAP_MASTER_KEY` 的值）和数据库一起保留，缺少它就无法解密已保存的凭据。

## 界面

- 页面与弹窗按设计稿实现：登录、首次设置、设置页（「账号」「登录方式」「API 令牌」三张卡片）、生成令牌、令牌已生成、修改密码。
- 所有文案提供中文和英文；深色与浅色主题都要可用，颜色只使用设计变量。
- 表单提交中按钮显示加载状态并禁止重复提交；接口出错时在表单顶部或对应字段旁显示错误，不能出现空白页。
- 需要二次确认的操作：吊销令牌、解除 OIDC 绑定、关闭密码登录、修改 Issuer 或 Client ID。

## 不在本期范围

- 多用户、角色、审计日志（v1 spec 决策 15，留待后续版本）
- 修改用户名
- 同时配置多个 OIDC 提供方
- SAML、LDAP、两步验证（TOTP、WebAuthn）
- 查看或踢出其他会话的会话管理页
- 删除令牌记录
- 通过 OIDC 声明（组、角色）做授权
