# opsnap 密钥库：服务器登录用的密码与私钥

> Status: Approved
> Owner: opsnap 维护者
> Last updated: 2026-10-20

**Objective:** 管理员在一个地方维护可复用的服务器登录密码和私钥；添加或编辑服务器时既可以选一条已保存的，也可以直接把凭据填在服务器表单里，并自己决定要不要把它存进密钥库。

**Hard invariant:** 密码、私钥和私钥口令加密后保存，接口和界面都不回显内容；任何一项失败都不能让服务器用错凭据或存下不完整的密钥。v1 的「失败或不完整的导出不能记为成功的快照」不受影响。

## Problem

1. **凭据跟着服务器走，重复且难改。** 现在每台服务器各自存一份 `auth_type`/`password`/`private_key`/`passphrase`（`internal/model/entity/server_entity/server.go:58`），十台机器同一个 root 密码就要粘十次；改密码要逐台打开抽屉（`frontend/src/pages/server-drawer.tsx` 的「认证」一节）。
2. **服务器列表看不出用的是哪份凭据。** 只显示认证方式「密码 / 私钥」（`frontend/src/pages/servers.tsx` 的 `AUTH_LABEL`），分不清「生产 root」和「旧机房 admin」。

## Actors and user stories

1. 作为**管理员**，我想把常用的密码和私钥存成几条带名字的「密钥」，这样加服务器时直接选一个。
2. 作为**管理员**，我想改一次密码就让用它的服务器全部生效，这样轮换密码不用逐台改。
3. 作为**管理员**，我想看到哪条密钥被哪些服务器使用，这样删之前知道会影响谁。
4. 作为**管理员**，我想在服务器表单里直接填一次性的密码或私钥、不强制进密钥库，这样只给一台机器用的凭据不会变成公共条目。
5. 作为**管理员**，我想在事后把某台机器上填的凭据「存成密钥」，这样不用重新输入一遍。

## Design decisions

标记：〔用户〕用户已决定；〔核实〕已从代码核实；〔推荐〕经用户确认的推荐方案。

| # | 决策 | 依据与否决方案 |
|---|---|---|
| 1 | 新增独立资源「密钥」（资源分组下的一页），密码和私钥都叫「密钥」，用类型区分〔用户〕 | 一处维护、多处引用。否决：继续让凭据内联在服务器里 |
| 2 | 一条密钥可以被多台服务器共用〔用户〕 | 同一台机器的同一种凭据本来就重复。否决：一条密钥锁定一台服务器 |
| 3 | 一条密钥只存一种内容：密码，或者私钥（+ 可选口令）〔推荐〕 | 类型即认证方式，列表和下拉里一眼可辨。否决：一条密钥同时存密码和私钥 |
| 4 | 服务器不存凭据，只存 `credential_id`；认证方式由密钥类型决定〔推荐〕 | 消除「服务器认证方式」与「密钥类型」两处可能不一致。否决：服务器自带 `auth_type` |
| 5 | 直接改未发布的 `servers` 迁移，不为旧数据写搬迁脚本〔用户〕 | 尚未发版，没有需要保留的线上数据 |
| 6 | 选密钥时只在服务器「用户」为空时填入密钥的默认用户〔推荐〕 | 已经手动填过的用户不被悄悄覆盖。否决：每次选中都覆盖 |
| 7 | 服务器表单的认证区有「用已保存的 / 直接填写」两种来源〔用户〕 | 不强迫先建密钥。否决：只能从已保存的里选 |
| 8 | 直接填写的凭据**默认不进密钥库**，由管理员勾选「同时存成密钥」决定〔用户〕 | 一次性凭据不该污染密钥列表。否决：直接填写一律自动存成密钥 |
| 9 | 私有的和共享的凭据放在同一张表，用 `shared` 标记区分〔用户〕 | 一条加密与引用路径，服务器始终只有一个 `credential_id`。否决：服务器另存一份私有凭据（两套来源、两套加密路径） |
| 10 | 每台服务器最多有一条私有凭据；勾选「同时存成密钥」是把这条私有凭据原地转成共享（改名字与标记），不复制〔推荐〕 | 转共享后旧值不残留，引用关系不变。否决：新建一条共享的、留下废弃的私有行 |
| 11 | 密钥页只列共享的密钥；私有凭据只能在那台服务器的抽屉里看和改〔推荐〕 | 密钥页是「可复用凭据」的清单，列出一次性凭据会淹没有用的条目。否决：都列出来并标灰 |
| 12 | 密钥名称唯一，仅约束共享的密钥〔推荐〕 | 下拉里靠名称辨认；私有凭据不需要名字 |
| 13 | 删除被服务器使用的共享密钥时拒绝，并列出这些服务器〔推荐〕 | 与 v1「被任务使用或被用作跳板的服务器不能删除」一致 |
| 14 | 删除服务器时一并删除它的私有凭据；共享凭据不动〔推荐〕 | 不留孤儿行 |
| 15 | 本次只做服务器登录凭据；任务的数据库密码、SOCKS5/HTTP 代理密码、SFTP 私钥不动〔用户〕 | 缩小改动面 |
| 16 | 轮换主密钥时一并重新加密密钥库〔核实〕 | `internal/repository/masterkey_repo/masterkey.go` 的 `Rekey` 必须覆盖新的表，否则轮换后这些凭据解不开 |
| 17 | 服务器列表增加「密钥」列：共享的显示名称与类型，私有的显示「直接填写」与类型〔推荐〕 | 一眼看出用的是哪一份、是不是公共的 |
| 18 | 密钥自己不能「测试连接」 | 测试需要一个目标主机和指纹，密钥本身没有这些；测试连接仍在服务器抽屉里 |
| 19 | 私钥类型的密钥保存公钥，列表与抽屉都能一直看到、复制、下载 `.pub`〔用户〕 | 公钥是明文，配 `authorized_keys` 时随时要用。否决：只在保存时显示一次 |
| 20 | 密码和私钥都能「随机生成」：密码 32 位、ed25519 私钥、口令可选 16 位〔用户〕 | 省去管理员自己想密码。否决：前端用 Web Crypto 生成私钥（浏览器里拼 OpenSSH 格式不可靠） |
| 21 | 生成只填进表单，不落库；保存后照旧不回显，与 v0.1.1 一致〔用户〕 | 否决：保存后单独弹一次「仅此一次可见」 |
| 22 | 复制密码走专用接口 `POST /credentials/:id/reveal`，一次返回一条明文；列表接口仍只说「有没有内容」〔用户〕 | 列表接口带明文会让任何打开页面的人批量拿到密码。否决：列表接口直接返回明文 |
| 23 | 生成的密码交给后端生成，用 `crypto/rand`；排除容易看错的 `0 O 1 l I`〔推荐〕 | 前端 `Math.random` 不可用于凭据 |

## 密钥页

位置是左侧边栏「资源 → 密钥」，路径 `/credentials`。参考 mockup（仅作佐证，以本文为准）：`.dev-kit/artifacts/2026-10-20-credential-library/mockups/`。

**列表：**

- 只列共享的密钥。私有凭据不出现在这里，只能在那台服务器的抽屉里改（见下一节）。
- 每行显示：名称、类型（密码 / 私钥）、默认用户、备注、**公钥或密码**、被哪些服务器使用（最多列 3 个名字，多于 3 个时后缀「等 N 台」；没有时写「没有共享它的服务器」）、最近修改日期，以及编辑、删除两个按钮。
- **公钥 / 密码**这一列：
  - 私钥类型显示公钥的第一行（`ssh-ed25519 AAAA…`，过长时截断，悬停可看全文）与一个复制按钮；
  - 密码类型不显示内容，只显示「密码 ·••••••••」与一个复制按钮；
  - 复制私钥类型的公钥时直接复制已返回的明文；复制密码时调用 `POST /credentials/:id/reveal` 拿到明文再写入剪贴板；
  - 复制成功后按钮变成绿色对勾与「已复制」，约 2 秒后复原；复制失败（例如浏览器拒绝写剪贴板或接口报错）时提示原因，不静默失败；
  - 没有内容的密钥（理论上不会出现）显示「—」并禁用复制。
- 列表底部一行说明：公钥是明文，可以直接复制到目标机的 authorized_keys；密码和私钥只能复制，界面上看不到内容。
- 顶部有搜索框，按名称和默认用户即时过滤（本地过滤，不发请求），右侧显示「共 N 条」。
- 状态：加载中显示骨架屏；读取失败显示出错原因与「重试」；一条都没有时显示「还没有密钥。添加后可以在服务器里选用。」；搜索无结果时显示「没有匹配「<关键词>」的密钥。」。
- 窄屏（宽度小于 `lg`）每行改为卡片式排列，名称与备注在上，类型、用户、使用者、日期依次向下。

**添加 / 编辑抽屉：**

- 从右侧抽屉打开，宽度与服务器抽屉一致。表单在内容区，底部一行「取消」和「添加」/「保存」。
- 字段：
  - **名称**（必填，最长 64 个字，不能与其他共享密钥重名）；
  - **类型**：分段控件「密码」与「私钥」；
  - 类型为密码时：**密码**（必填；编辑时留空表示保留已保存的值，输入框右侧有显示 / 隐藏切换）；
  - 类型为私钥时：**私钥**（必填，OpenSSH 或 PEM 格式；编辑时留空表示保留）与**私钥口令**（可选；编辑时留空表示保留）；
  - **默认用户**（可选，最长 64 个字，提示「选了这条密钥时，服务器上为空的『用户』自动填它」）；
  - **备注**（可选，最长 200 个字，只在本页显示）。
- **随机生成**（〔用户〕决策 20、21）：
  - 密码类型：密码输入框右侧有「随机生成」按钮，点一下用后端生成的 32 位密码填进输入框并切换成显示状态，可直接复制；说明文字写明「32 位，含大小写字母、数字和符号，去掉了容易看错的 0 O 1 l I，不满意就再点一次」。
  - 私钥类型：私钥下方有「随机生成私钥」按钮，生成 ed25519 私钥填进输入框；私钥口令旁有「随机」按钮，生成 16 位口令。
  - 生成只调用 `POST /credentials/generate`，返回内容填进表单，**不写库**；保存仍然走原来的添加/保存。
- **公钥**（〔用户〕决策 19）：
  - 私钥类型时，私钥输入框下方固定显示一块「公钥」：明文一行（可选中、可复制）、「复制公钥」与「下载 .pub」两个按钮、右侧显示指纹 `SHA256:…` 的前若干位。
  - 新建时粘贴（或生成）私钥后立刻显示由它算出的公钥，并标注「由刚粘贴的私钥算出，还没保存」；私钥为空时这块显示「粘贴私钥后这里会显示公钥」。
  - 编辑时私钥输入框留空（表示不修改）则显示已保存私钥对应的公钥，标注「已保存的私钥对应的公钥」；粘贴了新私钥则改为显示新私钥算出的公钥。
  - 私钥无法解析时，公钥块显示「私钥无法解析或口令错误」，不显示任何旧公钥，避免误导。
- 类型从一端切到另一端时，同时清空不属于新类型的那部分内容，保存时只写新类型需要的字段。
- 编辑一条被服务器使用的密钥时，抽屉底部显示「被这些服务器使用」，列出服务器名与 `用户@地址`，并写明「改这里的密码或私钥，上面这些服务器会一起生效」。
- 保存前在服务端校验：
  - 名称为空、超长或与其他共享密钥重名 → 提示对应的原因，停在抽屉里，不写入；
  - 类型为密码却没有密码，或类型为私钥却没有私钥（新建，或编辑时原本就没有）→ 提示「请填写密码」/「请粘贴私钥」；
  - 私钥无法用所给口令解析 → 提示「私钥无法解析或口令错误」；
  - 通过后密码、私钥、口令都用主密钥加密再写入，保存后提示「密钥已添加」/「密钥已保存」并关闭抽屉，列表刷新。
- 读取接口只返回「有没有密钥内容」（`has_secret`）与「有没有口令」（`has_passphrase`），不返回任何密文或明文。

**删除：**

- 没有被服务器使用：二次确认「删除密钥「<名称>」？删除后不能恢复。」，确认后删除并刷新。
- 被服务器使用：确认对话框里的主按钮不可用，并写明「有 N 台服务器使用这条密钥：<名字>。先在那些服务器上换成别的凭据，再删除。」
- 服务端同样拒绝，错误文案与上面一致（防止绕过界面）。

## 添加 / 编辑服务器

- 「认证」一节不再有裸露的「密码 / 私钥」分段控件和凭据输入框，改成两件事：**凭据来源**（分段控件「用已保存的 / 直接填写」）和对应的内容。
- **用已保存的**：一个可搜索的组合框。
  - 收起时显示所选密钥的图标、名称和类型标签；未选择时显示占位「选择密码或私钥」。
  - 展开后顶部是搜索框（按名称、默认用户过滤），下面是共享密钥列表，每项显示图标、名称、类型标签、默认用户，右侧显示「N 台在用」或「未使用」；底部固定一行「直接填写…」，点击切到直接填写。
  - 键盘：输入即过滤，`↓`/`↑` 移动，`Enter` 选中，`Esc` 关闭并把焦点还给触发按钮。
  - 一条共享密钥都没有时，列表区显示「还没有密钥」，底部同样有「直接填写…」。
  - 选中后，选择器下方一行摘要：默认用户 ·「没有口令」或「私钥带口令」·「还有 N 台服务器用它」。
- **直接填写**：
  - 先是类型分段控件「密码 / 私钥」，再是对应输入：密码（可显示 / 隐藏），或私钥（多行）+ 私钥口令（可选，可显示 / 隐藏）。
  - 下面一个默认**未勾选**的「同时存成密钥」：说明「勾选后这份凭据进密钥库，别的服务器也能选它；不勾选只属于这台服务器，在『密钥』页看不到」。勾选后展开**密钥名称**输入框，默认填服务器名，重名自动加序号，之后可以在密钥页改名。
  - 编辑一台已有私有凭据的服务器时，这一栏已填好（内容显示为「已设置」占位，不回显）；改密码或私钥就是改这条私有凭据，不新建。
  - 编辑一台正用着共享密钥的服务器时切到「直接填写」，表单从空白开始；保存后这台服务器改用一条新的私有凭据，原来那条共享密钥不受影响，也仍然被别的服务器使用。
- 选中的来源决定这次连接的认证方式。
- 选中共享密钥时，如果「用户」为空，就把密钥的默认用户填进去；「用户」已有内容时不动。切到直接填写不清空「用户」。
- 「测试连接」「保存」在既没有选中共享密钥、也没有填写直接填写内容时给出「选择密码或私钥」或「填写密码」/「粘贴私钥」，不发请求。测试连接会用当前的凭据连接填写的主机（与现在一样，只有目标主机指纹已核对方发送凭据）。
- 服务器列表的行内摘要从「密码，N 个任务」改为「<密钥名>，N 个任务」（私有凭据时为「直接填写，N 个任务」），并新增「密钥」列：共享的显示密钥名 + 类型；私有的显示「直接填写」+ 类型；窄屏下这一列与地址、连接路径一样折行显示。
- 删除密钥导致服务器失去凭据的情况不会出现：被使用的共享密钥删不掉。

## 接口

新增 `/api/v1/credentials`，只操作共享密钥：

- `GET /credentials` 列出共享密钥，按名称排序（中文按名称本身，不另做拼音排序），每项带被哪些服务器使用（`servers`：id、名称、地址与用户），以及私钥类型的 `public_key`（明文）。
- `GET /credentials/:id` 读取一条共享密钥。
- `POST /credentials`、`PUT /credentials/:id`：整体提交 `name`、`kind`（`password` | `ssh_key`）、`password`、`private_key`、`passphrase`、`username`、`note`。`POST` 时密码或私钥必填；`PUT` 时对应字段留空表示保留已保存的值。返回保存后的条目。
- `DELETE /credentials/:id`：被服务器使用时返回错误，附上使用者名称。
- `POST /credentials/generate`：生成但不保存，返回 `kind` 对应的内容：
  - `kind=password` → `{password}`（32 位）；
  - `kind=ssh_key` → `{private_key, public_key}`，可选带 `passphrase`（16 位）；
  - 不写库、不进日志，也不出现在任何列表响应里。
- `POST /credentials/:id/reveal`：返回这一条密钥的一次性明文 `{kind, password}` 或 `{kind, private_key, passphrase}`，供界面复制密码或私钥用。只允许共享密钥；不存在或私有凭据按「密钥不存在」处理。
  - 用 POST 而不是 GET，避免被缓存、被浏览器历史或代理记录；
  - 需要登录会话或 API 密钥（与其他接口一致）；
  - 请求与响应都不写进日志；响应带 `Cache-Control: no-store`。

服务器接口：

- `ServerInput` 改为：
  - `credential_id`：使用一条已保存的共享密钥时填它的 ID；
  - `credential_id` 为 0 时表示直接填写，此时提交 `auth_type`（`password` | `ssh_key`）、`password`、`private_key`、`passphrase`；占位「已设置」表示保留这台服务器已有的私有凭据，留空表示没有；
  - `share_as`：直接填写时可选，填了就把它存成这个名称的共享密钥（新建或原地转共享），空表示保持私有。
- `Item` 返回 `credential`：`{ id, kind, name, shared, username, note, has_secret, has_passphrase, public_key }`，不再返回 `auth_type`、`password`、`private_key`、`passphrase`。私有凭据的 `name` 为空串；`public_key` 只在私钥类型时非空。
- `Test` 请求与 `ServerInput` 同形，凭据占位按服务器已保存的值解析。
- 删除服务器时，若它的凭据是私有的，一并删除；共享的保持不动。

错误码在 `internal/pkg/code` 新增：密钥不存在、密钥字段不合法（名称/类型/密码/私钥/口令/备注各给出原因）、密钥名称重复、密钥没有内容、密钥被服务器使用。密码与私钥的内容一律不出现在错误文案、日志和接口响应里。

## 存储与迁移

`servers` 表去掉 `auth_type`、`password`、`private_key`、`passphrase` 四列，加 `credential_id INTEGER NOT NULL REFERENCES credentials(id)`。新建 `credentials` 表：

| 列 | 说明 |
|---|---|
| `id` | 自增主键 |
| `name` | 共享凭据的名称，非空；私有凭据为空串 |
| `kind` | `password` 或 `ssh_key` |
| `password`、`private_key`、`passphrase` | 主密钥加密后的密文，没有就是空串 |
| `username` | 默认用户，可为空 |
| `note` | 备注，可为空 |
| `public_key` | 私钥类型保存时由私钥算出的公钥（`authorized_keys` 一行，明文）；密码类型为空串 |
| `shared` | 1 = 共享，0 = 服务器私有 |
| `createtime`、`updatetime` | Unix 秒 |

共享密钥的名称唯一，用部分索引 `CREATE UNIQUE INDEX uk_credentials_shared_name ON credentials (name) WHERE shared = 1`；每台服务器最多一条私有凭据，由服务端保证（`credential_id` 指向的行 `shared = 0` 且只被这一台服务器引用）。

按〔用户〕决策 5，直接修改 `migrations/202610150004_servers.go`：`credentials` 表在同一迁移里先建，`servers` 改为引用它；不写数据搬迁。迁移可前进、可回滚（回滚先删 `servers` 再删 `credentials`）。

`internal/repository/masterkey_repo` 的 `Rekey` 遍历 `credentials` 的 `password`、`private_key`、`passphrase`，`servers` 只保留各代理跳的 `password`。

## 安全与隐私

- 密码、私钥、口令与 v1 其他凭据一样，用主密钥以 AES-256-GCM 加密后存入 SQLite，轮换主密钥时一并重新加密。
- 界面与接口默认不回显内容：编辑时留空即保留；列表、下拉、服务器摘要只显示名称、类型、默认用户和「有没有口令」。
- 唯一的例外是 `POST /credentials/:id/reveal`：管理员主动点「复制」时，一次性取回这一条的明文。接口不回写日志、响应 `Cache-Control: no-store`；公钥则始终是明文，可以直接查看与复制。
- 测试连接会把当前凭据发往表单里填写的地址与端口，这是管理员可见、主动触发的行为（API 密钥拥有与管理员相同的权限，与 v1 决策 18 一致）。
- 密钥的名称与备注是明文，提示文案里不要让人把密码粘进备注。

## Out of scope

- 任务里的数据库密码、SOCKS5 / HTTP 代理密码、SFTP 私钥改用密钥库
- 密钥的分组、标签、权限或按团队隔离（v1 决策 11：只有一个管理员）
- 密钥的导入导出、自动轮换、到期提醒
- 密钥自己的「测试连接」
- 服务器凭据的审计日志（谁在什么时候用了哪条密钥）
- 复制动作的审计记录（`reveal` 目前不记日志，与 v1 其他管理操作一致）
- 把私有凭据共享给多台服务器之外的其他共享方式（例如「从服务器 A 的私有凭据复制到 B」）
