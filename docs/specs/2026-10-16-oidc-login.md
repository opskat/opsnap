# opsnap OIDC 单点登录

> Status: Approved
> Owner: opsnap 维护者
> Last updated: 2026-10-16

**Objective:** 管理员把 opsnap 唯一的管理员账号绑定到自建 Gitea（或其他 OIDC 提供方）上的一个账号，之后可以用这个账号登录面板，并可以关闭用户名密码登录。

**Hard invariant:** 只有绑定的那个提供方账号（issuer + sub 完全一致）能经 OIDC 得到会话；密码登录处于关闭状态时一定存在绑定，并且始终能用环境变量临时打开密码登录，管理员不会被锁在外面。v1 的不变量不受影响。

## Problem

1. **只能用密码登录。** v1 的登录只有用户名 + 密码（[v1 spec「管理面板：交互与视觉」](2026-10-15-opsnap-v1.md#管理面板交互与视觉)），「单点登录」被列为不做的事（v1 spec「Out of scope」）。用户要用自己的 Gitea 账号登录面板（用户陈述）。

## Actors and user stories

1. 作为**管理员**，我想用自己的 Gitea 账号登录 opsnap，这样不用再单独记一个密码。
2. 作为**管理员**，我想关掉密码登录，这样面板上只剩一个由 Gitea 把关的入口。
3. 作为**管理员**，我想在 Gitea 出故障时仍能进入 opsnap，这样不会因为登录方式被锁在外面。

## Design decisions

标记：〔用户〕用户已决定；〔核实〕已从代码或环境核实；〔推荐〕经用户确认的推荐方案。

| # | 决策 | 依据与否决方案 |
|---|---|---|
| 1 | 用标准 OIDC（授权码 + PKCE），不写 Gitea 专用代码〔推荐〕 | Gitea 是标准 OIDC 提供方，同一套实现也能接 Authentik、Keycloak。否决：Gitea 专用 OAuth2 接口 |
| 2 | 管理员先用密码登录，再在设置里绑定一个提供方账号；只认这个账号的 issuer + sub〔用户〕 | sub 不随用户名、邮箱变化，也不会被别人复用。否决：按用户名或邮箱白名单——字段可被改动或复用；按 Gitea 组织 / 团队放行——opsnap 只有一个管理员，分不出是谁在操作 |
| 3 | 密码登录可以关，默认开着；环境变量 `OPSNAP_PASSWORD_LOGIN=1` 可强制打开〔用户〕 | 关掉后入口更少；Gitea 故障时能用环境变量恢复。否决：始终保留密码登录 |
| 4 | 提供方配置放在面板「设置 → 单点登录」，Client Secret 用主密钥加密保存〔用户〕 | 与 v1 其他配置一致，改配置不用重启。否决：环境变量 / config.yaml |
| 5 | 登录按钮文字可配置，默认「Gitea」〔用户〕 | 用户的提供方是 Gitea |
| 6 | 回调地址由管理员填写的「面板对外地址」拼成，不从请求头推断〔推荐〕 | opsnap 常放在反向代理后面，请求里的 Host 不一定是浏览器看到的地址。否决：按请求的 Host 和 X-Forwarded-* 推断 |
| 7 | 本 spec 取代 v1 spec「Out of scope」中「单点登录」一项；「多用户和权限」仍然不做〔用户〕 | — |

## 设置 → 单点登录

设置页在「通用」「API 密钥」之后增加第三个标签「单点登录」，分三块。参考 mockup（仅作佐证，以本文为准）：`.dev-kit/artifacts/2026-10-16-oidc-login/mockups/`。

**提供方：**

- 字段：
  - Issuer 地址（必填，http 或 https 的绝对地址；提示「Gitea 填它的 ROOT_URL」）；
  - Client ID（必填）；
  - Client Secret（第一次保存时必填；之后显示「已设置」，留空表示不修改，内容不回显）；
  - 按钮文字（必填，最长 32 个字符，默认「Gitea」；字段下方预览「登录页显示『用 Gitea 登录』」）；
  - 面板对外地址（必填，http 或 https 的绝对地址，例如 `https://opsnap.example.com`）。
- 字段下方显示回调地址 `<面板对外地址>/api/v1/auth/oidc/callback`，带复制按钮，并说明要填到提供方 OAuth2 应用的重定向 URI 里。面板对外地址末尾的 `/` 不会造成双斜杠。
- 点击「保存并检查」时，opsnap 读取 `<Issuer>/.well-known/openid-configuration`（超时 10 秒）：
  - 读取失败、不是合法的 OIDC 发现文档、或文档里的 issuer 与填写的不一致时，不保存，在按钮上方显示原因，写明请求的地址和底层错误（例如 `connection refused`、超时、HTTP 状态码、「提供方声明的 issuer 是 …」）。
  - 成功时保存并提示「已保存，提供方检查通过」。
- 已有绑定时修改 Issuer 或 Client ID，保存前确认「保存后会解除当前绑定」；确认后保存并解除绑定。只改 Client Secret、按钮文字或面板对外地址不影响绑定。
- 可以清空整个配置（「停用单点登录」，需确认）；停用同时解除绑定。

**绑定账号：**

- 未保存提供方配置时，「绑定」按钮不可用，提示「先保存提供方配置」。
- 已配置、未绑定时，显示「还没有绑定」和「绑定 <按钮文字> 账号」。点击后浏览器跳到提供方授权；授权完成回到「设置 → 单点登录」：
  - 成功：显示「已绑定 <显示名>」，下面一行是 sub、issuer 和绑定时间。显示名取 `preferred_username`，没有时取 `name`，再没有时显示 sub。显示名只用于展示，不参与身份判断。
  - 失败：页面顶部显示红色提示「绑定失败：<原因>」，原因与下文登录失败的原因相同（例如「提供方拒绝了授权（access_denied）」），绑定状态不变。
- 绑定只能由已经用会话登录面板的管理员在浏览器里发起；用 API 密钥不能发起绑定。
- 已绑定时显示「解除绑定」，需确认（「解除后不能再用 <按钮文字> 登录，直到重新绑定。当前会话不受影响」）。要换账号时先解除再重新绑定。

**密码登录：**

- 开关「允许用户名密码登录」，默认开。改动立即保存。
- 没有绑定时开关不可关，提示「绑定账号后才能关闭」。
- 关闭前确认：「之后只能用 <按钮文字> 账号 <显示名> 登录。<按钮文字> 不可用时，用环境变量 OPSNAP_PASSWORD_LOGIN=1 重启容器可以临时打开密码登录。API 密钥不受影响。」
- 密码登录关闭期间：Issuer、Client ID 不可修改，「解除绑定」和「停用单点登录」不可用，旁边写明原因（避免绑定失效后无法登录）。
- 任何解除绑定的操作（解除绑定、修改 Issuer 或 Client ID、停用单点登录）都会同时把保存的开关改回「开」，所以「密码登录关闭」时一定存在绑定。

## 登录

**登录页的形态**（未登录也能读取：是否允许密码登录、是否启用单点登录、按钮文字）：

| 状态 | 登录页显示 |
|---|---|
| 未配置或未绑定 | 与 v1 相同，只有用户名密码表单 |
| 已绑定，密码登录开 | 用户名密码表单，下面一条「或」分隔线，再下面是次要样式的「用 <按钮文字> 登录」 |
| 已绑定，密码登录关 | 只有主样式的「用 <按钮文字> 登录」，下方一行「密码登录已关闭。<按钮文字> 不可用时，见部署说明里的恢复方法。」 |

尚未创建管理员时，登录页仍跳到首次设置，与 v1 相同。

**登录流程：**

1. 点击「用 <按钮文字> 登录」后，按钮变成不可用并显示「正在跳转到 <按钮文字>…」，浏览器跳到提供方授权页。请求的 scope 是 `openid profile`。
2. 提供方带授权码回到回调地址。opsnap 依次检查，任何一项不通过都不建立会话：
   - 这次登录请求由同一个浏览器发起、没有被用过、发起后不超过 10 分钟（state）；
   - 用授权码和 PKCE（S256）换取令牌；
   - id_token 的签名（用提供方公布的 JWKS 校验）、issuer、audience（等于 Client ID）、有效期、nonce；
   - id_token 的 issuer + sub 与绑定完全一致。
3. 通过后建立与密码登录相同的会话（HttpOnly Cookie，7 天），跳到概览页；登录前访问的页面（`next`）同样只接受站内路径。
4. 不通过时跳回登录页，在按钮上方显示原因，不建立会话：

| 情况 | 提示 |
|---|---|
| sub 或 issuer 与绑定不一致 | 「<按钮文字> 账号 <显示名> 不是绑定的管理员账号，换成绑定的账号再试。」 |
| state 缺失、过期、已用过或不是这个浏览器发起的 | 「登录请求已过期（超过 10 分钟）或已用过，请重新点击登录。」 |
| 用户在提供方拒绝授权，或提供方返回错误 | 「<按钮文字> 拒绝了授权（<error>）。」 |
| 连不上提供方，或提供方响应异常 | 「连不上 <按钮文字>（<Issuer>）：<底层错误>。稍后再试。」 |
| id_token 签名、issuer、audience、有效期或 nonce 校验失败 | 「<按钮文字> 返回的身份令牌无效：<哪一项>。」 |
| 单点登录未启用或未绑定 | 「单点登录未启用。」 |

- 回调里的错误原因经服务端整理后才显示，不把提供方返回的任意文本原样插进页面；提示和日志都不包含授权码、令牌或 Client Secret。
- OIDC 登录失败不计入 v1「连续错误 5 次锁定 10 分钟」的密码错误次数，也不受该锁定影响。

**密码登录关闭时：**

- 用户名密码登录接口返回 403，说明「密码登录已关闭，请用 <按钮文字> 登录」。登录页如果还是旧页面，提交后显示这句话。
- 修改密码仍然可用（需要原密码），供环境变量恢复时使用。
- API 密钥的认证不受影响。

**环境变量恢复：**

- 设置环境变量 `OPSNAP_PASSWORD_LOGIN=1`（或 `true`）重启后，不管设置里保存的是什么，密码登录都可用，登录页同时显示两种方式。其他取值或不设置时按设置里保存的值。
- 此时「设置 → 单点登录」里开关显示为开且不可操作，下方用警告色写明「环境变量 OPSNAP_PASSWORD_LOGIN=1 正在强制打开密码登录（设置里保存的是『关闭』）。恢复访问后，去掉这个变量并重启容器。」；保存的值是「开」时只写明正在被环境变量强制打开。
- 强制打开期间，「密码登录关闭期间」的那些锁定不生效；按上一节，解除绑定会同时把保存的开关改回「开」。
- README 的部署说明写明这个变量和恢复步骤。

**退出：** 只结束 opsnap 的会话，不退出提供方。

## 安全与存储

- Client Secret 与 v1 其他凭据一样，用主密钥以 AES-256-GCM 加密后存入 SQLite；轮换主密钥时一并重新加密。读取设置的接口只返回「是否已设置」。
- 绑定只保存 issuer、sub、显示名和绑定时间，不保存提供方的令牌。
- 进行中的登录请求（state、nonce、PKCE verifier）最多保留 10 分钟，用过即失效；opsnap 重启后进行中的登录请求全部失效，提示同「已过期」。
- 绑定与浏览器的关联用一个只在登录流程中使用的 HttpOnly、SameSite=Lax Cookie。
- 提供方可以是 http 地址（内网 Gitea）。HTTPS 证书按镜像里的系统根证书校验；自签名 CA 不在本次范围内（可自行挂载 CA 并设置 `SSL_CERT_FILE`）。
- 设置页的单点登录配置和密码登录开关可以被 API 密钥修改（v1 决策：API 密钥拥有与管理员相同的权限），但绑定只能在浏览器里完成。

## Out of scope

- 多个提供方、多个绑定账号、多用户和权限
- 通过 OIDC 首次创建管理员（首次设置仍然设置密码）
- 按提供方的组、组织或团队放行
- 退出 opsnap 时同时退出提供方（RP-initiated logout）
- 面板里配置自签名 CA
- 用 OIDC 令牌调用 HTTP API（API 仍然只认 API 密钥）
