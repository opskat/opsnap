# opsnap v1：自托管备份编排与管理面板

> Status: Approved
> Owner: opsnap 维护者
> Last updated: 2026-10-22

**Objective:** 管理员在一台常开的小主机上部署 opsnap，通过 Web 面板配置线上服务器的数据库和目录，按计划把加密后的备份写入群晖或飞牛 NAS；出问题时能被告知，需要时能浏览并下载任意快照里的内容。

**Hard invariant:** 任何一次失败或不完整的导出都不能被记为成功的快照；NAS 上只存密文。

## Problem

1. **线上数据没有离线、可控的备份。** 用户需要把线上环境的数据库（MySQL、PostgreSQL、Redis、MongoDB）和服务器文件备份到自己的 NAS，并有后台管理面板（用户陈述）。
2. **三台机器互不相同。** 备份程序跑在用户自己的常开服务器或小主机上，线上服务器和 NAS 是另外两台机器（用户陈述）。数据库有跑在 Docker 容器里的，也有云数据库（用户陈述）。
3. **工作目录是空的。** 仓库目前没有任何文件，也不是 git 仓库（已核实）。同组织的 opskat 项目使用 Go + cago 后端、React + shadcn/ui 前端（已核实：`opskat/go.mod`、`opskat/frontend/components.json`）。

## Actors and user stories

1. 作为**管理员**，我想在一个面板里配置服务器、存储位置和备份任务，这样不用在每台机器上写脚本。
2. 作为**管理员**，我想一眼看出哪些任务失败、哪些很久没有成功，这样能及时处理。
3. 作为**管理员**，我想在 opsnap 所在机器损坏时，仍能用自己保管的密钥恢复 NAS 上的备份。
4. 作为**管理员**，我想从任意快照里挑出文件或数据库导出并下载，这样能手动恢复。
5. 作为 **AI 助手或脚本**，我想用 API 密钥通过 HTTP API 查询状态、读取日志、触发备份，这样管理员可以把巡检和操作交给 AI。

## Design decisions

标记：〔用户〕用户已决定；〔核实〕已从代码或环境核实；〔推荐〕经用户确认的推荐方案。

| # | 决定 | 依据与否决方案 |
|---|---|---|
| 1 | 自研单个 Go 服务：cago 框架，SQLite 存储，内嵌 React + shadcn/ui 的 SPA，打成一个 Docker 镜像〔用户〕 | 与 opskat 技术栈一致。否决：现成 Backrest + hook 脚本——数据库导出、凭据和失败语义都散落在脚本里；把 restic 当 Go 库嵌入——restic 没有稳定的库 API |
| 2 | 部署在常开的服务器或小主机上，由 opsnap 主动拉取〔用户〕 | 线上服务器和 NAS 都不需要装任何东西。否决：服务器装 Agent 推送；经对象存储中转 |
| 3 | 备份格式用 restic 仓库〔用户〕 | 块级去重、AES-256 加密、快照与保留、完整性校验都有现成实现。否决：普通压缩包——没有去重，加密和存储后端要自己实现 |
| 4 | 存储后端支持本地目录（NFS/SMB 挂载）、SFTP、S3 兼容、restic REST Server、WebDAV（经 rclone）〔用户〕 | 直接复用 restic 和 rclone 的后端。否决：只支持挂载目录 |
| 5 | 文件备份先用 rsync 增量同步到本机镜像目录，再对镜像生成快照〔用户〕 | 公网流量最少。否决：tar 流式传输——每次全量，恢复单个文件要先取出整包 |
| 6 | 数据库连接只有两种：「经 SSH」= 经服务器（可带代理链）建 SSH 隧道连到数据库地址；「直连」〔用户〕 | 导出工具在 opsnap 一侧运行，服务器上什么都不用装；容器内的数据库由用户填写容器 IP。否决：「容器内」模式（在服务器上 docker exec） |
| 7 | 导出工具内置在镜像里，pg_dump 等统一用最新版〔用户确认 #1〕 | 新版 pg_dump 可以导出旧版本服务端。代价：要维护镜像里的工具版本 |
| 8 | 导出数据经管道直接写入 restic，本机不落盘〔推荐〕 | 不需要本机磁盘，也不留明文 |
| 9 | 每个存储位置有两把 restic 密钥：opsnap 密钥（加密保存在 SQLite）和可选的恢复密钥（只给用户看一次，opsnap 不保存）〔推荐〕 | opsnap 所在机器损坏时，用户仍能独立恢复。否决：只有一把由 opsnap 保管的密钥 |
| 10 | 服务器认证支持密码、私钥、私钥 + 口令；连接支持代理链，每一跳可以是 SSH 跳板、SOCKS5 或 HTTP CONNECT〔用户〕 | 用户要求支持代理链和密码 |
| 11 | 只有一个管理员账号〔推荐〕 | 个人工具。否决：多用户和权限 |
| 12 | 程序重启后不补跑错过的任务，改由「太久没有成功」告警兜底〔推荐〕 | 小主机常开，补跑会和正常计划叠在一起。告警能同时发现宕机、调度卡住、持续失败 |
| 13 | 通知只做通用 Webhook〔用户〕 | 否决：内置企业微信、钉钉、邮件等渠道 |
| 14 | 恢复只做浏览和下载，不写回线上〔用户〕 | 避免误操作覆盖线上数据 |
| 15 | AI 接入只做 HTTP API + API 密钥 + OpenAPI 文档〔用户确认 #2〕 | 否决：MCP 服务端（以后再说） |
| 18 | API 密钥不区分权限，任何有效密钥都拥有与管理员相同的权限〔用户〕 | 第一版从简。否决：只读 / 可运行 / 完全控制三档权限 |
| 16 | 面板用左侧边栏导航，主题色沿用 opskat 的 primary〔用户〕 | 否决：顶部导航；自定义紫色 |
| 17 | 本机文件镜像默认保留明文，可在设置里改为备份后清空〔推荐〕 | 保证增量传输。清空的代价是每次全量传输 |

## 部署与运行环境

- **形态**：一个 Docker 镜像，内含 opsnap 程序、restic、rclone、rsync、openssh-client，以及 mysqldump、pg_dump、mongodump、redis-cli。数据目录挂载到容器的 `/data`，里面存 SQLite、文件镜像和 restic 缓存。
- **主密钥**：从环境变量 `OPSNAP_SECRET_KEY` 读取。缺失时程序拒绝启动，并在日志里说明原因，不会用默认值继续运行。
- **时区**：可在设置中配置，默认 `Asia/Shanghai`。所有计划时间都按这个时区解释。

## 服务器与代理链

- **添加服务器**：在右侧抽屉里填写名称、地址、端口、用户，再选认证方式（密码，或私钥 + 可选口令）。密码、私钥、口令都加密后存入 SQLite；保存后界面只显示「已设置」，不回显内容。
- **代理链**：
  - 按顺序配置 0 到多跳。每一跳可以是 SSH 跳板（从已添加的服务器中选择）、SOCKS5 或 HTTP CONNECT 代理；代理可选填用户名和密码。
  - 各跳可以上移、下移、删除。opsnap 严格按「本机 → 第 1 跳 → … → 目标」的顺序逐跳建立连接。
- **测试连接**：
  - 逐跳显示连通结果和延迟。
  - 任何一跳失败时，标出是哪一跳、失败原因是什么（超时、认证失败、指纹不符），后面的各跳不再尝试。
- **主机指纹**：
  - 第一次连接某台 SSH 主机（包括作为跳板的主机）时，显示它的 SHA256 指纹，请管理员核对；核对通过之前不能保存。
  - 之后每次连接，指纹一旦变化就拒绝连接，相关任务的这次运行记为失败，并给出「主机指纹已变化」的原因。
- **服务器列表**：显示名称、地址、认证方式、连接路径（直连，或依次列出各跳）、状态（正常 + 延迟 / 从某时起连不上），以及使用它的任务数。

## 存储位置与加密

- **添加存储位置**：
  - 填写名称、类型和对应的地址参数。
  - 保存时先测试能否访问。位置为空就初始化一个新的 restic 仓库；已经是 restic 仓库，就要求输入它现有的密码后再接入。
- **修改存储位置**：
  - 只能改名称和地址参数，类型和两把密钥都不变。
  - 保存时用 opsnap 密钥验证仍能打开仓库，验证不通过就保持原状。
  - 已保存的凭据不显示内容：留空表示沿用，填写则替换。改了地址或用户名、而凭据留空时，保存报错并要求重新填写（已保存的凭据只属于原来的地址）。
  - SFTP 主机公钥按地址沿用：地址不变时不需要重新核对，地址一改就要重新获取并核对。
- **两把密钥**：
  - **opsnap 密钥**：添加时自动生成，用主密钥加密后存入 SQLite，日常备份都用它。
  - **恢复密钥**：添加时默认勾选「同时生成一把恢复密钥」。界面只显示这一次，并提供复制和下载；opsnap 不保存。必须勾选「已存进密码管理器」才能保存。
- **「密钥」对话框**（每个存储位置都有）：
  - 查看两把密钥的状态和创建时间。
  - 更换 opsnap 密钥：先加新密钥，再删旧密钥，任何一步失败都保持原状。
  - 生成或移除恢复密钥。
  - 下载恢复包。恢复包包含仓库地址、恢复步骤和 restic 命令，不包含任何密钥。
- **缺少恢复密钥时**：存储位置列表和对话框里显示警告「没有恢复密钥」。
- **防止写进本机磁盘**：
  - 对「本地目录」类型，初始化时在仓库根目录写入标记文件 `.opsnap-repo`。
  - 每次运行前检查这个文件。找不到就判定 NAS 未挂载，本次运行失败，原因写「没有挂载」，不向该路径写入任何数据。
  - 面板上该存储位置标红，并提供「重新检查」。
- **NAS 上的数据**：只有 restic 加密后的数据。经 S3 用 HTTP 传输时，内容同样已经加密。
- **存储位置列表**显示：
  - 实际占用 / 原始数据量和去重压缩比
  - 快照数、NAS 剩余空间
  - 加密状态、密钥数量、上次校验时间
- **维护操作**：校验数据、清理空间、下载恢复包、解除仓库锁。解除仓库锁需要二次确认。
- **定期维护**：每个存储位置每周自动执行一次清理空间（prune）和抽样校验（check），默认周日 06:00。维护运行时独占该存储位置，不与写入它的备份同时进行。

## 备份任务

**配置项：**

- **数据源**：MySQL、PostgreSQL、Redis、MongoDB、文件。每种显示官方 logo；文件用文件夹图标。
- **连接（数据库）**：
  - 选「经 SSH」或「直连」。
  - 经 SSH 时选一台服务器，并填写「从这台服务器上看的」数据库地址（容器就填容器 IP）。
  - 再填数据库用户和密码，密码加密保存。
- **库**：
  - 填好连接后，面板读取并列出所有库及其大小，管理员勾选要备份的；系统库不可选。
  - 也可以打开「全部，含以后新建」。
  - 读取失败时，原地显示原因并提供重试。
- **连接（文件）**：选一台服务器，填写一到多个绝对路径和排除规则（写法同 rsync）。
- **存到**：以单选卡片列出存储位置及剩余空间；未挂载的不可选。
- **计划**：每小时、每 6 小时、每天、每周或 cron 表达式；按天和按周时还要填时刻。表单上显示下一次运行时间。
- **保留**：
  - 「7 天」「30 天」：保留这段时间内的每一次备份。
  - 「长期」：最近 7 天每天留一份，再往前到 4 周每周留一份，再往前到 6 个月每月留一份。
  - 「自定义」：同一套句式，三个数字可以修改。
  - 表单上用一句话写出结果（如「共约 17 个快照」），并配一条时间轴示意。
- **高级**（默认收起，标题行显示当前值）：超时（默认 2 小时）、限速、压缩（自动 / 最大 / 关闭）、导出或 rsync 的附加参数。

**表单交互：**

- **右侧摘要**：固定显示「来源 / 存到 / 加密 / 计划 / 保留」五行，随表单内容实时更新。
- **测试连接**：逐项显示检查结果。失败项给出原因；有修复办法时直接给出可复制的命令，例如缺少权限时给出对应的 GRANT 语句。
- **保存**：
  - 有字段校验错误时不能保存，错误显示在对应字段下方。
  - 连接测试没通过时可以保存，但要先确认一次。
- **保存并运行**：保存后立即开始一次运行，并跳转到运行详情。

**任务列表：**

- 每行显示：名称、来源 → 存储位置、计划和下次运行时间、最近 14 天的运行带、上次结果、立即运行按钮。
- 可以按「全部 / 需要处理 / 已暂停」筛选，并按名称、服务器或路径搜索。
- 更多操作：编辑、查看快照、复制为新任务、暂停或恢复计划、删除。删除需要二次确认；删除任务不删除已有快照。

## 一次运行

**同一个任务不会同时运行两次。** 按计划触发时如果上一次还在运行，这一次跳过并记录原因。手动触发时如果正在运行，按钮不可用。

运行依次经过以下几步：

1. **预检**
   - 存储位置可以访问，并且已经初始化；本地目录类型还要能找到挂载标记文件。
   - 到服务器的连接（含代理链和指纹校验）能建立。
   - 任何一项失败，本次运行就失败，并写出具体原因。
2. **导出并写入快照**
   - **数据库**：导出命令的输出经管道直接写入 restic，本机不落盘。MySQL 用一致性快照导出，PostgreSQL 用自定义格式，MongoDB 用 archive 格式，Redis 取 RDB；都不压缩，交给 restic 压缩。导出进程以非零退出码结束时，不生成快照，本次运行失败。
   - **文件**：先 rsync 增量同步到本机镜像目录，再对镜像生成快照。rsync 报告「同步期间文件消失」时，本次记为「有警告」，快照照常生成；其他 rsync 错误都记为失败，不生成快照。
3. **清理旧快照**：按保留规则删除这个任务的过期快照。
4. **记录并通知**：写入运行记录，按通知规则发送 Webhook。

**超时**：超过任务设置的超时，终止整个进程组；本次运行失败，原因写「超时」，不留下快照。

**停止**：管理员在运行详情页点击「停止运行」并确认后，效果与超时相同，原因写「手动停止」。

**运行记录**包含：触发方式（计划 / 手动 / 某个 API 密钥）、开始时间、耗时、各步骤状态、处理的数据量、新增的存储量、快照 ID 和完整日志。

**日志**：运行详情页实时显示日志，可以只看警告。日志里不出现任何密码、私钥或密钥；凭据通过环境变量或标准输入传给子进程，不出现在命令行参数里。

**保留期限**：运行记录和日志默认保留 90 天，可在设置中修改。

## 调度与告警

- 由 opsnap 内置的调度器按各任务的计划触发；全局同时运行的任务数默认 2，可在设置中修改。
- 程序重启后，只按下一次计划时间继续，不补跑停机期间错过的运行。
- **「太久没有成功」检查**：任何未暂停的任务，如果超过设定时长（默认 48 小时）没有一次成功的运行，就触发一次告警；之后恢复成功时，触发「恢复正常」。

## 概览页

- **顶部**：
  - 用一句话说明当前状态，例如「3 个任务需要你处理，其余 3 个运行正常」。全部正常时也用一句话说明。
  - 旁边显示受保护的数据总量、NAS 上实际占用、快照总数。
- **需要处理**：
  - 列出失败、有警告、太久没有成功的任务。每项写清原因、从何时开始，并给出直接的操作（重新运行、查看日志、检查存储位置）。
  - 没有需要处理的任务时，不显示这一区块。
- **运行时间线**：
  - 每个任务一条轨道，横轴按真实时间比例排列。实心点是已经运行过的，颜色表示结果；空心点是计划中的运行；一条主题色竖线标出「现在」。
  - 可切换 7 天 / 30 天；悬停在点上显示时间和结果，点击任务名进入编辑。
  - 宽度小于 768px 时，改为每天一格的 14 天运行带。
- **存储位置**：每个存储位置一张卡片，显示实际占用与原始数据量的对比条和去重压缩比；未挂载的标红。

## 快照与下载

- 先选择一个任务，左侧按时间列出它的快照。每个快照显示时间、新增的数据量（附一根长短对比条），以及被保留的原因（最近、每天、每周、每月）。
- **文件快照**：右侧显示带大小和修改时间的目录树，勾选文件或目录后，打包成 `.tar.gz` 下载。下载以流式输出，本机不生成临时文件。
- **数据库快照**：列出导出文件，每个可以下载为 `.sql.gz` 或对应格式；同时给出一条可复制的恢复命令示例。opsnap 不会写回任何线上数据库。
- **下载失败**：比如仓库被锁或 NAS 不可访问，在面板上提示原因，不提供半截文件。

## 通知

- 可配置一个 Webhook 地址和可选的请求头，以 JSON POST 发送。
- **事件**：备份失败（默认开）、恢复正常（默认开）、太久没有成功（默认开，阈值 48 小时）、每次成功（默认关）。
- **消息内容**：事件类型、任务 ID 和名称、运行 ID、开始时间、耗时、错误摘要、上次成功时间，以及指向面板的链接。
- **测试**：「发一条测试消息」会显示对方返回的状态码。
- **发送失败**：重试 3 次（指数退避）后放弃，并在运行记录里注明「通知发送失败」。

## HTTP API 与 API 密钥

- 面板使用的 REST API 就是对外提供的 HTTP API，前缀 `/api/v1`。OpenAPI 文档地址是 `/api/v1/openapi.json`。
- **API 密钥**：
  - 在「设置 → API 密钥」中创建，填写名称和过期时间（30 天 / 90 天 / 永不）。
  - 完整密钥只显示一次，前缀为 `osk_`。opsnap 只保存密钥的哈希。
- **权限**：不区分权限。任何有效的 API 密钥都能做管理员在面板上能做的所有事，包括修改配置和下载快照内容（明文）。创建对话框里用一句话提示这一点。
- **请求与拒绝**：请求带 `Authorization: Bearer <key>`。密钥无效、已撤销或已过期时返回 401。
- **密钥列表**显示名称、前缀、最近使用时间、创建时间和过期时间，可随时撤销，撤销立即生效。
- 由 API 密钥触发的运行，在运行记录里写明是哪把密钥。

## 管理面板：交互与视觉

**登录：**

- 用户名 + 密码。连续错误 5 次锁定 10 分钟，错误提示里写明还剩几次。
- 会话用 HttpOnly Cookie 保存。

**导航：**

- 左侧边栏分三组：
  - 概览、备份任务、快照、运行记录
  - 资源：服务器、存储位置
  - 系统：通知、设置
- 侧边栏底部依次是「正在备份」卡片（任务名、已处理的数据量和速度，点击进入运行详情；没有任务在运行时显示一行说明）和账号菜单（修改密码、退出），旁边是深色模式切换。
- 宽度小于 1024px 时，侧边栏收进左侧抽屉。
- 「备份任务」旁边显示需要处理的任务数。

**设置：**

- **通用**：管理员账号、同时运行的任务数、运行记录保留天数、时区、「备份后清空文件镜像」开关、主密钥状态（以及轮换入口）。
- **API 密钥**：见上一节。

**视觉系统：**

- **色板**：
  - 界面骨架几乎没有颜色：石灰纸色底（`#f3f3f0`）、白色面板、墨色文字（`#17181b`），再加两级灰色文字。
  - 颜色只用来表达两类信息：
    - 状态：成功绿、警告赭黄、失败朱红。
    - 主题色：opskat 的 primary，浅色 `oklch(0.55 0.22 260)`、深色 `oklch(0.63 0.2 260)`。它同时表示「现在」和「正在运行」。
  - 浅色、深色两套都有。
- **字体**：IBM Plex Sans 和 IBM Plex Mono（用 @fontsource 本地打包，不走 CDN），中文回退到苹方或微软雅黑。等宽字体只用于路径、地址、快照 ID、命令和日志。
- **标志**：三层「地层」，最上面一层用主题色，代表最新的快照。
- **组件**：shadcn/ui（在 opsnap 仓库内生成），外观全部由上述 token 决定。
- **文案**：
  - 用状态和动作直接说话，不写引导性的长段说明。
  - 错误提示写清发生了什么、怎么处理。
  - 同一个动作在按钮、提示和记录里用同一个名字。

**状态、可访问性与响应式：**

- **页面状态**：概览、任务列表、快照页都有加载中（骨架屏）、空状态、出错三种状态。
  - 空状态的概览页用三步引导：添加服务器 → 添加存储位置 → 创建任务。
  - 出错状态写明哪个接口超时，并提供重试。
- **可访问性**：
  - 所有交互元素都能用键盘操作，并有可见的焦点样式。
  - 只有图标的按钮都带可读的标签。
  - 尊重系统的「减少动态效果」设置。
  - 状态从不只靠颜色区分，始终配有文字或图标。
- **响应式**：宽度从 390px 到桌面都可以使用；表格类列表在窄屏下改为卡片式的行。

## 安全与隐私

- **存储的凭据**：服务器密码、私钥及口令、数据库密码、代理密码、opsnap 密钥，都用主密钥以 AES-256-GCM 加密后存入 SQLite。
- **API 密钥**：只存哈希。
- **恢复密钥**：不存储。
- **面板监听**：默认只建议在内网或组网环境访问。面板本身不提供 TLS，需要公网访问时由用户在前面加反向代理。
- **本机明文**：只有文件镜像目录（`/data/mirror`）存放明文，设置页明确标出，并提供「备份后清空」开关。

## Out of scope

- 写回线上环境（文件还原到服务器、数据库导入）
- 在服务器上安装 Agent、容器内 docker exec 导出
- 多用户和权限、单点登录
- 内置的企业微信、钉钉、飞书、邮件、Telegram 等通知渠道
- MCP 服务端（以后再考虑）
- 与 opskat 资产打通（以后可以从 opskat 导入服务器）
- 停机期间错过的运行自动补跑

## Testing decisions

| 接缝 | 验证什么 | 已有参考 |
|---|---|---|
| 命令构建（纯函数）：任务配置 → restic、rsync、各导出工具和 SSH 代理链的参数与环境变量 | 各数据源和连接方式生成正确的命令；凭据只出现在环境变量里，不进入参数 | 无 |
| 运行状态机（替身执行器） | 预检失败、导出非零退出、rsync 退出码 24 与其他错误、超时、手动停止、并发跳过，分别得到正确的结果，并且没有多余的快照 | 无 |
| 调度与告警（可注入时钟） | cron 与预设的下次运行时间、重启不补跑、太久没有成功、恢复正常 | 无 |
| 保留规则 | 预设和自定义规则映射成正确的 forget 参数，界面上显示的快照数量估算正确 | 无 |
| 凭据加密与 API 密钥 | 加密往返；缺少主密钥时拒绝启动；密钥哈希、过期、撤销后返回 401 | 无 |
| 集成测试（docker-compose：sshd、SOCKS5 代理、MySQL、PostgreSQL、Redis、MongoDB、SFTP 与本地仓库） | 每种数据源都走通「备份 → 生成快照 → 下载内容与源数据一致」；代理链两跳连通；导出中途失败时不生成快照；本地仓库缺少标记文件时拒绝写入；指纹变化时拒绝连接 | 无 |
| 前端组件测试（vitest） | 任务表单的校验和摘要、保留规则的句式与估算、时间线的点位计算、存储位置修改表单的预填与凭据占位 | opskat 前端已有 vitest 配置 |

**集成测试环境**〔用户〕：

- 集成测试在一台 Docker 主机（opsctl 资产）上通过 opsctl 启动容器运行。
- 这台机器上还运行着其他在用的服务（包括各类数据库），并占用了它们的默认端口。因此测试环境必须遵守：
  - 所有测试容器放在独立的 compose 项目（`opsnap-it`）和独立网络里，不向宿主机发布默认端口。
  - 测试只连接自己启动的容器，不连接机器上已有的任何数据库。
  - 启动、清理只针对 `opsnap-it` 项目，不对其他容器、镜像、卷做任何操作；测试结束后删除本项目的容器、网络和卷。
  - 测试数据全部是虚构的。

无法自动化、在收尾阶段人工验证的有：

- 群晖和飞牛真机上的 SFTP 与 NFS/SMB 挂载
- 面板在浅色、深色、窄屏下的视觉效果
- 用恢复包和恢复密钥在另一台机器上用 restic 独立恢复一次
