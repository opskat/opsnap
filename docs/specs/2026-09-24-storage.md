# 存储、kopia 仓库与加密密钥

> Status: Approved
> Owner: OpsNap 产品负责人
> Last updated: 2026-09-24

**Objective:** 管理员能在「存储」页添加本地目录或 S3 兼容存储。每个存储对应一个加密的 kopia 仓库，其密钥由 OpsNap 托管，同时由用户离线保存。已有仓库只能用正确的密钥解锁，任何操作都不会覆盖或删除存储里已有的数据。

**Hard invariant:**

1. OpsNap 不删除、不覆盖存储中已有的任何数据：
   - 已有的 kopia 仓库只能解锁后使用；
   - 不为空、又不是 kopia 仓库的位置一律拒绝；
   - 删除存储只删除 OpsNap 里的记录。
2. S3 Secret Key 和仓库密钥不以明文落盘，也不写入日志。
   - 仓库密钥只在两种情况下返回给前端：设置密钥时，以及再次验证身份后查看时。
   - Secret Key 保存后不再返回给前端。
3. OpsNap 创建的仓库，用户可以只凭离线保存的密钥和 kopia 官方命令行打开，不依赖 OpsNap。

标记说明：〔已核实〕= 查证过源码或官方资料；〔用户决定〕= 本轮讨论中用户已确认；〔默认〕= 按常规做法先定、用户已认可设计。

## 问题

1. **还没有地方存放备份。** 主干上「存储」页仍是占位页〔已核实，main 6357874〕，后续的备份任务没有目的地。
2. **备份必须加密，而且在 OpsNap 损坏后仍能取回。** 这来自 v1 spec 的用户故事 3 与决策 10〔用户决定〕。
3. **同一个位置可能已有仓库。** 重装 OpsNap、迁移或误操作后，用户会把存储指向已有仓库，此时绝不能覆盖〔用户决定，v1 spec〕。

## 角色与用户故事

1. 作为**管理员**，我想在 OpsNap 主机的目录或 S3 桶里建立加密的备份仓库，并在创建时拿到密钥离线保存。
2. 作为**管理员**，我想在重装 OpsNap 后，用离线保存的密钥重新连上原来的仓库，继续使用。
3. 作为**管理员**，我想在需要时再次查看或下载某个存储的密钥，但必须先证明是我本人。
4. 作为**运维工程师**，我想在 OpsNap 完全不可用时，用 kopia 官方命令行和密钥直接恢复数据。

## 设计决策

| # | 决策 | 依据与被否决的方案 |
|---|---|---|
| 1 | 存储类型只有本地目录和 S3 兼容存储〔用户决定，v1 spec 决策 11〕 | 否决：SFTP 等其他后端 |
| 2 | 每个存储对应一个 kopia 仓库（kopia v0.23.1 作为 Go 库嵌入），仓库始终加密〔已核实〕 | kopia 仓库必须设密码，只提供 AES256-GCM-HMAC-SHA256 与 CHACHA20-POLY1305-HMAC-SHA256 两种加密；v0.23.1 要求 Go 1.25.8，本项目为 1.26。否决：提供“不加密”选项（kopia 不支持） |
| 3 | 仓库密钥就是该 kopia 仓库的密码，可由系统生成，也可由用户自设；OpsNap 用主密钥加密托管〔用户决定，v1 spec 决策 10〕 | 定时任务需要无人值守；用户能直接拿密钥去用 kopia 命令行。否决：每个任务一把密钥、服务端不托管 |
| 4 | 创建后可以再次查看或下载密钥，但要重新验证身份〔用户决定〕 | 避免“当时没存好”就永久丢失。否决：只显示一次（服务器坏了就找不回数据）、随时可看不验证（会话被盗即可导出全部密钥） |
| 5 | 删除存储只删 OpsNap 的记录和托管的密钥，数据保留〔用户决定〕 | 防止误删。否决：可选同时删除远端数据、不允许删除 |
| 6 | 所有字段都可以编辑，包括位置〔用户决定〕；改到新位置时按新位置重新走仓库流程〔用户决定〕 | 否决：只能改名称和凭据、只允许指向同一个仓库 |
| 7 | 本地目录可以浏览整个文件系统，只列目录，并标出目录状态〔用户决定〕 | 否决：限定在配置的根目录内（部署时要多配一项）、同时列出文件（暴露文件名，对选目录没有帮助） |
| 8 | 查看密钥、浏览和新建目录只能用浏览器会话；API 令牌能管理存储本身〔默认〕 | 延续认证 spec「令牌不能拿到秘密」的原则 |

## 存储列表

**前提**：已登录。

- 侧栏「存储」进入列表。每行显示：
  - 名称与类型；
  - 位置：本地目录为绝对路径加“OpsNap 主机”，S3 为 `s3://<bucket>/<前缀>` 加 Endpoint；
  - 密钥指纹；
  - 状态标签，以及最近一次测试时间或失败原因。
- 状态为以下三种之一：
  - **正常**：最近一次测试能连接，并能用托管密钥打开仓库。
  - **密钥不正确**：能连接，但托管密钥打不开仓库，例如仓库密码在 OpsNap 之外被改过。这一行提供“重新解锁”，流程同「解锁已有仓库」，成功后改用新输入的密钥。
  - **无法连接**：显示具体原因，例如目录不存在或不可写、`Access Denied`、`no such host`、Bucket 不存在。
- 每行操作有“测试连接”“编辑”，以及更多菜单中的“查看密钥”“下载密钥文件”“删除存储”。
- 测试连接只在以下时机进行：
  - 创建时；
  - 保存编辑时；
  - 点击“测试连接”时；
  - 完成重新解锁时。
- 打开列表不会自动测试所有存储，显示的是最近一次测试的结果和时间。
- 没有存储时显示空状态，引导“新建存储”。加载失败时显示错误与重试，不出现空白页。

## 新建存储

**前提**：已登录。

**第一步：填写与测试。**

- 选择类型（本地目录 / S3 兼容存储），填写名称。
- 名称为 1–64 个字符，不能与已有存储重名。
- **本地目录**：填写 OpsNap 主机上的绝对路径，也可以点“浏览…”选择（见「浏览本地目录」）。
  - 路径不存在时，保存时会自动创建，权限为 0700。
  - 相对路径不合法，在字段旁提示。
- **S3 兼容存储**的字段：
  - Endpoint，不含协议，可以带端口；
  - Region，可选；
  - Bucket；
  - 路径前缀，可选，下方实时显示最终位置 `s3://<bucket>/<前缀>`；
  - Access Key、Secret Key；
  - “使用 HTTPS”开关，默认开；
  - “跳过证书校验”开关，默认关。
  - OpsNap 不创建 Bucket，Bucket 不存在时提示“Bucket 不存在”。
- 同一位置不能被两个存储使用：本地为规范化后的绝对路径，S3 为 Endpoint、Bucket 与前缀相同。重复时提示“该位置已被存储「X」使用”。
- “测试连接”检查三件事：能否连接、能否写入（写入后删除一个测试对象）、目标位置属于哪种情况。

**第二步：按目标位置的情况进入不同流程。**

| 目标位置 | 结果 |
|---|---|
| 为空（本地目录不存在也算） | 进入「设置加密密钥」 |
| 已是 kopia 仓库 | 进入「解锁已有仓库」 |
| 不为空，也不是 kopia 仓库 | 拒绝：“目标位置不为空，且不是 kopia 仓库”，不能保存 |
| 无法连接或不可写 | 显示原因，不能保存 |

只有流程成功完成后才保存存储，并在列表中显示为“正常”。中途取消或失败，不留下存储记录，也不在目标位置留下任何数据；在空位置设置密钥时，仓库在确认后才创建。

## 设置加密密钥

**前提**：目标位置为空。

- 默认“系统生成（推荐）”：
  - 生成 24 个随机字母和数字，每 4 个一组，用 `-` 连接，连字符也是密钥的一部分；
  - 提供复制、下载密钥文件、重新生成；
  - 下方显示指纹和加密算法。
- 也可以切换为“我自己设密码”：至少 12 个字符，两次输入一致。
- 警告框说明：
  - OpsNap 会加密保存一份密钥，用于定时任务和恢复；
  - 服务器损坏、重装或被清空后，只有用户手上的这份能解开备份。
- 必须勾选“我已保存这把密钥，并明白丢失后数据无法恢复”，“启用加密”按钮才可用。
- 启用后，以这把密钥作为密码，用 AES256-GCM-HMAC-SHA256 在目标位置创建 kopia 仓库，然后保存存储。
- 创建时如果发现目标位置已不为空（测试之后被写入），就放弃，并按第二步的规则重新判断，不会覆盖。
- **指纹**：密钥 SHA-256 摘要的前 4 位与后 4 位，用大写十六进制表示，例如 `3F9A···C218`。指纹只用于核对是不是同一把密钥，不能从它推出密钥。
- **密钥文件**：纯文本，文件名为 `opsnap-<存储名>-key.txt`，内容包括：
  - 密钥本身；
  - 指纹；
  - 存储位置；
  - 用 kopia 命令行连接这个仓库的示例命令。

## 解锁已有仓库

**前提**：目标位置已是 kopia 仓库。新建存储、更改位置、列表中的“重新解锁”都会进入这里。

- 对话框显示：
  - 仓库位置；
  - 创建时间：取仓库格式文件（`kopia.repository`）的写入时间，取不到时不显示；
  - 快照数量。
- 可以粘贴密钥，也可以上传密钥文件。上传的文件可以是 OpsNap 导出的密钥文件，也可以是只含密钥的文本文件，首尾空白会被忽略。
- 密钥错误时，显示“密钥不正确，无法解开这个仓库。已连续 N 次失败。”
  - 次数只统计当前对话框内的尝试，关闭对话框即清零。
  - 失败不锁定。
- 提示框说明：如果这个仓库不是你的，或者密钥已经丢失，可以换一个空的位置新建仓库；已有的快照不会被删除，但无法再读取。
- 解锁成功后，这把密钥成为该存储的托管密钥。
- 仓库本身不做任何改动：不改密码，不改格式。

## 浏览本地目录

**前提**：用浏览器会话登录，正在填写本地目录存储。API 令牌调用浏览与新建目录接口返回 403。

- 打开位置：输入框中的路径存在时打开该路径，否则打开 OpsNap 数据目录的上级目录。
- 顶部是“上一级”按钮和可点击的路径面包屑，可以一直到 `/`。
- 列表只显示子目录（包括通过符号链接指向的目录），不显示文件，按名称排序。每个目录标出一种状态：
  - **空目录**
  - **kopia 仓库**
  - **非空**
  - **不可写**：OpsNap 进程对它没有写权限。
- 点击目录进入该目录。无权读取的目录显示“无权访问”，不能进入。
- 底部可以在当前目录下新建文件夹，权限为 0700。名称不能为空，不能含 `/`，不能与已有目录重名；失败时显示原因，例如没有写权限。
- 页脚显示当前选中的路径，“选择此目录”把它填回输入框。
- 选择之后仍按「新建存储」的规则测试和判断：选中“非空”目录同样会被拒绝。

## 编辑存储

**前提**：已登录。所有字段都可以编辑。

- 表单与新建相同。
  - Secret Key 显示“已保存（加密存储）”，留空表示不修改。
  - 名称与位置的唯一性规则不变。
- **位置没变**，只改名称、凭据、Endpoint、Region、HTTPS 或证书选项：
  - 保存前重新测试连接，并确认托管密钥仍能打开同一个仓库；
  - 失败时不保存，并显示原因，例如新的 Access Key 没有权限。
- **位置变了**，即类型、本地路径、Bucket 或路径前缀有变化：
  - 保存前二次确认，说明原位置的仓库保持不动，但此存储之后看不到其中的快照。
  - 确认后按新位置判断：
    - 为空：用当前托管密钥在新位置新建仓库，不再弹出设置密钥；
    - 已是 kopia 仓库：进入「解锁已有仓库」，成功后此存储改用这把密钥；
    - 不为空且不是仓库，或无法连接：拒绝，存储保持原样。
- 编辑失败或中途取消时，存储保持编辑前的全部设置。

## 查看与下载密钥

**前提**：用浏览器会话登录。API 令牌调用返回 403。

- “查看密钥”和“下载密钥文件”都需要先验证身份：
  - **密码登录开启时**：输入当前管理员密码。
    - 错误时提示“登录密码不正确”，并计入认证 spec 中的登录保护失败次数。
    - 登录保护锁定期间同样被拒绝。
  - **密码登录关闭时**：按钮变为“使用 <OIDC 显示名称> 重新验证”，跳转 IdP。
    - 以已绑定身份回来后，5 分钟内可以查看，并自动回到该存储的查看界面。
    - 回调的错误处理与 OIDC 登录相同。
- 验证通过后显示密钥、复制和下载按钮、指纹，以及用 kopia 命令行打开仓库的示例命令。
- 每次查看都要重新验证，对话框关闭后不保留。

## 删除存储

**前提**：已登录。

- 确认框说明：只删除 OpsNap 中的记录和托管的密钥，存储里的备份数据不会被删除。
- 确认框同时提醒：以后重新添加这个位置必须提供密钥，并提供“先下载密钥文件”入口（需要验证身份）。
- 删除后，列表中不再显示该存储，OpsNap 本机上该仓库的缓存也一并清理。
- 后续轮次有任务引用该存储时，禁止删除，并提示引用它的任务。本轮还没有任务，不涉及。

## 敏感数据

- S3 Secret Key 与仓库密钥都用认证 spec 中的主密钥加密后存入数据库。
- 日志中不出现 Secret Key、仓库密钥、密钥文件内容，也不出现 S3 请求签名。
- 除「查看与下载密钥」「设置加密密钥」外，任何接口都不返回仓库密钥。任何接口都不返回 Secret Key。

## 产品文档

README 必须说明：

- 每个存储都是标准的 kopia 仓库；
